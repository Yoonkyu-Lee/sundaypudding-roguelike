# 마이그레이션 & 검증 인프라 계획 (Claude Code 세션 지시 문서)

> **이 문서의 목적**: 현재 TypeScript 코어를 향후 Rust로 포팅(마이그레이션)하기 위한
> 사전 작업으로, **검증 인프라를 전면 재구축**하기 위한 계획과 맥락을 정리한다.
> Claude Code 세션은 이 문서를 읽고, **현재 코드를 직접 리뷰하여** 검증 규칙 목록을
> 독립적으로 도출한다. (별도 문서 `INVARIANTS-FROM-REPO.md`와 교차 검증할 예정)
>
> **중요**: 이 문서는 "무엇을·왜"를 정의한다. "어떻게(구체 규칙)"는 세션이 코드를 보고 채운다.

---

## 0. 한 줄 요약

> 현재 ~120개 테스트를, **게임 정합성을 전수 커버하는 정교한 검증 스위트**로 갈아엎는다.
> 이것이 이 게임의 "coremark + RTL assertion" 에 해당하는 검증 인프라다.
> 단, RTL처럼 비트 단위가 아니라 **게임 로직(관측 가능 동작) 단위**의 100% 일치를 목표한다.

---

## 1. 배경 — 왜 지금 이 작업을 하는가

### 1.1 최종 목표 (장기)
- 렌더링을 **웹(DOM) → 네이티브(예: Rust + Godot, HD-2D)** 로 마이그레이트.
- 그 과정에서 **게임 로직 코어(`src/core/`)도 TypeScript → Rust 로 포팅**.
- 코어는 이미 렌더링 의존 0(헤드리스)이라, 로직 포팅과 렌더러 교체는 분리 가능.

### 1.2 핵심 제약 — 결정론은 1급 기능 요구사항
- 설계 문서 8.3: **시드 결정론 + 리플레이 + 이벤트 로그**는 "있으면 좋은" 게 아니라
  세이브/리플레이가 의존하는 **기능의 뼈대**다.
- 따라서 포팅 후 **"같은 시드 + 같은 행동 → 동일한 이벤트 로그"가 100% 보장**되어야 한다.
  이것이 깨지면 세이브·리플레이가 깨진다. → **로그 일치는 타협 불가**.

### 1.3 현재 검증의 한계 (세션이 인지해야 할 문제)
- 현재 테스트(~120개)는 대부분 **directed test**(특정 시나리오 단건 검증)다.
  유용하지만, **무작위 대량 자극(stress)** 과 **상시 불변식(assertion)** 이 빠져 있다.
- `autoRun`은 존재하나 **6개 시드 × 항상 0번 선택**만 돈다.
  → coremark를 6번, 매번 같은 분기로만 돌리는 것과 같다. 명령 공간의 극히 일부만 커버.
- 사람의 검수는 100% 웹 렌더링 플레이로만 이뤄져, 헤드리스 검증의 사각이 방치돼 있다.

## 2. 검증 철학 — RTL 검증의 게임 버전 (단, 추상화 수준이 다름)

CPU/RTL 검증과의 의도적 매핑. **신호·비트 단위가 아니라 게임 로직 단위**로 내린다.

| RTL 검증 개념 | 이 게임의 대응물 | 추상화 수준 |
|---|---|---|
| Directed test (AES/SHA 벡터) | 기존 단건 시나리오 테스트 (리팩터해 보존) | 특정 케이스 |
| Random/stress (coremark) | **무작위 행동 스트레스 런** (수만 시드 × 랜덤 합법 행동) | 대량 자극 |
| SVA assertion (사이클 불변식) | **불변식 assertion** (매 step 게임 규칙 검사) | 상시 규칙 |
| Golden model 대조 | **differential harness** (TS↔Rust 이벤트 로그 diff) | 출력 일치 |
| ULP/부동소수점 정합성 | **수치 타입 정책** (부동소수점 일치 / 정수화) | 수치 함정 |

### 2.1 "일치"의 경계 정의 — 무엇을 보고 무엇을 안 보나
**관측 가능한 게임 동작만 비교**한다. 내부 구현은 자유.

- ✅ **비교 대상 (관측 인터페이스)**:
  - 이벤트 로그 시퀀스(`GameEvent[]`) — 종류·순서·필드값
  - 최종/중간 상태 중 `Observation` 으로 노출되는 것 (HP, shield, pos, statuses, cooldowns, formation, phase, 서열)
  - 합법 행동 목록(`getLegalActions`)
- ❌ **비교 안 함 (구현 내부)**:
  - 함수 호출 순서, 변수명, 메모리 레이아웃
  - 로그/관측에 안 남는 중간 계산
- 근거: 설계 8.2 "결정에 필요한 모든 정보가 observation에 있다(픽셀에 숨은 정보 0)".
  검증도 **observation 경계에서만** 판정하면 게임적으로 충분하다.

## 3. 3개 자극·판정 레이어 (관계 명확화)

자극은 1종, 판정은 2종이 그 위에 얹힌다. (즉 "층 2 자극 → 층 1·3 판정")

### 3.1 자극: 무작위 행동 스트레스 런 (= coremark)
- 현재 `autoRun`의 "6시드 0번 선택"을 **수천~수만 시드 × 시드 결정 무작위 합법 행동**으로 확장.
- 매 턴 `getLegalActions()` 에서 **시드 기반으로 무작위 선택**(결정론 유지: 같은 시드 → 같은 스트레스 런).
- 전투뿐 아니라 **런 전체**(맵 이동·보상·상점·인카운터·층 전환)까지 무작위로 주파.
- 측정 지표:
  - 크래시/패닉 **0건** (TS throw / Rust panic 어느 쪽도 불가)
  - 교착(런이 안 끝남) **0건** — 스텝 상한 가드로 검출
  - (포팅 시) 로그 일치율 **100%**

### 3.2 판정 A: differential harness (= golden 대조) — *포팅 시점 한정*
- TS 코어 = golden model, Rust 코어 = DUT.
- 같은 시드+행동 시퀀스를 양쪽에 넣고 **이벤트 로그를 이벤트 단위로 diff**.
- **역할은 포팅 검증으로 한정** — 포팅 완료 후 TS가 폐기되면 짝이 사라져 역할 종료.
- **단, 지금 미리 "TS↔TS 자기 일치"(같은 시드 2회 실행이 동일 로그)로 harness를 먼저 구축**해
  결정론 자체를 검증하고, 포팅 때 그대로 재사용한다.

### 3.3 판정 B: 불변식 assertion (= SVA) — *영구 자산*
- 매 step(또는 매 이벤트) 후, **절대 깨지면 안 되는 게임 규칙**을 검사.
- 무작위 스트레스 런이 도는 내내 상시 작동. 위반 시 `(시드, 턴, 위반 규칙, 상태 스냅샷)` 덤프.
- **포팅과 무관하게 영구히 남는다** — 신기능·밸런스 변경 시에도 회귀를 잡는다.
- 부수 효과: **지금 TS 코어의 숨은 버그부터 드러낸다** → 포팅 전 청소.

### 3.4 수치 타입 정책 (= ULP 함정 차단)
- 포메이션 총량보존에서 `+4/3` 등 **분수**가 발생(코드의 `round1`, `attackPower` 분배).
- TS `number`(IEEE754 double) ↔ Rust 수치 타입 불일치 시 **반올림 한 끗 차이로 로그가 갈림**.
- 정책 둘 중 택일(세션이 코드 보고 권고):
  1. 포팅 시 `f64` 로 엄격히 일치시키고 반올림 지점(`Math.round`)을 정확히 복제, 또는
  2. 분배 연산을 **정수/고정소수점**으로 재설계(권장 가능성 높음 — 결정론에 더 안전).
- 어느 쪽이든 **반올림이 일어나는 모든 지점을 목록화**해야 한다.

## 4. 작업 범위 — 테스트 인프라 전면 재구축

### 4.1 기존 ~120 테스트 처리
- **삭제 금지, 보존 후 리팩터**: 유용한 directed 케이스는 살린다.
- **분류·모듈화**: 도메인별(전투/상태/포메이션/끼어들기/런/메타/장착/그래프)로 재정리.
- 중복 제거, 명명 규칙 통일, 공용 헬퍼(`testutil`) 정비.

### 4.2 신규 구축 (이 작업의 핵심)
1. **무작위 스트레스 런 러너** (시드 결정 무작위 선택, 전투+런 전체, 스텝 가드)
2. **불변식 assertion 모듈** (매 step 검사 훅 + 위반 덤프)
3. **differential/self-consistency harness** (같은 시드 2회 → 로그 동일 검증; 포팅 시 TS↔Rust 확장)
4. **수치 반올림 지점 목록 + 정책 결정 문서**
5. **불변식 규칙 카탈로그** (세션이 코드 리뷰로 도출 — §5)

### 4.3 성공 기준 ("마이그레이션 준비 완료"의 정의)
- [ ] differential(self) harness 존재 + 결정론 자기일치 통과
- [ ] 무작위 스트레스 런: 수만 시드, 크래시 0 / 교착 0
- [ ] 불변식 카탈로그가 스트레스 런 전체에서 위반 0
- [ ] 수치 타입 정책 확정 + 반올림 지점 전수 목록화
- [ ] 기존 directed 테스트 리팩터·분류 완료(회귀 보존)

## 5. 세션에게 요청 — 불변식 규칙을 코드에서 도출하라

> **이 절이 세션의 핵심 과제다.** 아래는 "추측"이 아니라 **`src/core/` 코드를 직접 읽고
> 실제로 강제되(거나 되어야 하)는 규칙"을 카탈로그로 만들라는 요청이다.**

### 5.1 도출 방법
1. `combat/`(flow, turnOrder, damage, status, targeting, skills, interrupt, winCheck, formation),
   `run/`(graph, layers, run, shop, encounter, items), `util.ts`, `types/` 를 정독.
2. 각 모듈에서 **불변식 후보**를 찾는다. 특히 다음 신호에 주목:
   - `Math.max(0, …)`, `clamp(…)`, `Math.min(hpMax, …)` 같은 **경계 강제** 코드
   - "…해야 한다 / 불변식 / 보존 / 재방문 불가" 류 **주석**
   - 정렬·서열·커서 진행의 **순서 보장**
   - 자원 보존(포메이션 총량, 골드 수지), 단조성(쿨다운 감소 등)
3. 각 규칙을 **검사 가능한 술어(predicate)** 형태로 표현. (예: "∀ unit: hp ≥ 0")
4. 규칙마다 **근거(파일/함수/주석)** 를 명시.
5. 규칙을 **카테고리·심각도(critical/normal)** 로 분류.

### 5.2 반드시 검토할 카테고리 (체크리스트 — 누락 없이)
- **유닛 상태 무결성**: HP 하한/상한, shield 하한, alive 일관성(hp 0 ↔ alive=false, 단 불사 예외)
- **죽음/생존**: 죽은 유닛은 행동·타겟·서열 진행에서 제외(단 타임라인엔 잔존), 불사 1턴 생존 규칙
- **턴/라운드 서열**: 한 라운드에 생존 유닛이 정확히 1회 정규 행동, 커서 단조 전진,
  끼어들기는 cursor+1 삽입·정규 턴에서만·연쇄 방지, 동점 정렬 결정론(uid tiebreak)
- **데미지/쉴드**: 쉴드→HP 순서, 관통=쉴드 무시, 공포=쉴드 잠식(HP 효율 불변), 무적=피해 0,
  최종 데미지 ≥ 0, 반올림 지점
- **상태이상**: 스택/지속 0 이하 시 제거, DoT/HoT 트리거 시점(turnStart/turnEnd/onAction),
  정화=버프만 잔존, speedMod 부호 의미
- **타겟팅/이동**: 위치 마스크 준수, 이동은 이동기 보유자만, col 범위 클램프(0..3),
  같은 편 같은 칸 점유 불가(이동 충돌 거부)
- **합법성**: `step`은 불법 행동(쿨다운 중/빙결) 거부, 빈 합법목록이면 skip만 가능
- **런 진행(그래프)**: 재방문 불가(전진만), 모든 활성 노드는 clear 도달 가능,
  층-그래프 도달성, 클리어=층 종료
- **경제/메타**: 골드 음수 불가, 구매 시 정확 차감·항목 제거(재구매 방지), 숙련도 tier 게이팅
- **종료성**: 모든 스트레스 런은 유한 스텝 내 won/lost 도달(교착 없음)

### 5.3 산출물 형식
- 별도 파일 `INVARIANTS-FROM-CLAUDE-CODE.md` 로 작성.
- 각 규칙: `[ID] [카테고리] [심각도] 서술 — 술어 — 근거(파일:함수) — 검사 시점(매 step / 라운드 경계 / 스트레스 런 종료)`
- 작성 후, 사람이 별도 문서(`INVARIANTS-FROM-REPO.md`)와 **교차 검증**하여 누락·과잉을 조정한다.

## 6. 작업 순서 (권장)

1. **(지금) 불변식 카탈로그 도출** (§5) — 코드 리뷰 기반.
2. 불변식 assertion 모듈 구현 + 기존 코어에 적용 → **현재 버그부터 검출**.
3. 무작위 스트레스 런 러너 구현 → assertion 두들기기.
4. self-consistency harness(같은 시드 2회 일치) 구축.
5. 수치 반올림 지점 목록화 + 타입 정책 결정.
6. 기존 ~120 테스트 리팩터·분류.
7. (이후 별도 단계) Rust 포팅 → differential harness 를 TS↔Rust 로 확장.

> **포팅(7)은 1~6이 끝나기 전에는 시작하지 않는다.** 검증 인프라가 포팅의 안전망이다.
