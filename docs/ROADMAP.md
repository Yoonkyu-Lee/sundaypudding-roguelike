## 🧭 확정된 게임 모델 (인터뷰 종합)

- **레퍼런스 = 슬레이 더 스파이어.** 모든 런은 **0(최초 상태)에서 시작**, 빌드·전직·아이템·골드는 **그 런 안에서만**, 런 끝나면 전부 리셋. "지속성과 직결되는 건 런 그 자체."
- **영구 성장 = 오직 "숙련도 → 그 캐릭터 스킬 풀 확장" 하나** (그마저도 미니멀·디자이너 회의적). **메타 재화·본산 영구 투자 루프 없음**(의도된 미니멀리즘, Q2/Q15).
- **롱텀 동력 우선순위 (Q12/Q13):** ① **빌드 실험**(넓은 스킬 풀 × 전직 조합) → ② **난이도 숙달·기록**(종결/지속 컨텐츠) → ③ **캠페인 서사**(정기 추가). 수직 성장이 약한 모델이라 **수평(빌드)·숙달(기록)**이 기둥.
- **전직(전직 시스템) = 런 중심 빌드 다양성의 새 엔진** (1순위 동력의 심장). **런 한정**(끝나면 리셋, Q9), **편도·무상**(전직 가능 노드 한정, Q10), **분기 트리**(직업 컨셉별 상위 스킬, Q11), **스킬 세트 교체**(Q8). 전직은 **전용 노드 + 쉼터(체력 회복 우호 노드)**에서, **노드당 전직 가능 인원 제한**(전용 노드 2~3명·쉼터 1명, Q7/Q10).
- **모드 (Q16 A·Q17·Q19):** 의미 있되 **런이 중심**. 기본 모드 = **20~30분 런**. **종결·지속 컨텐츠 = 정통 로그라이크 모드**(길게 1시간+, "성장 뽕맛"용, **처음부터 오픈**). 캐릭/런/난이도는 진행 해금, 종결 모드만 클리어 무관 오픈.
- **완성·엔딩 (Q5/Q14):** 숙련도는 **상한**(맥스=그 캐릭 "완성"). 엔딩 = "질릴 때"가 사실상 엔딩 — 로그라이크 랜덤성이 동력. 서사 엔딩은 정기 추가분.

## 🧭 엔지니어 원칙 — 엔진과 도구, 콘텐츠는 디자이너

- **우리(엔지니어)가 만드는 것 = ① 엔진 프리미티브(`engine/spr-core`) + ② 저작 도구(`web/src/ui/editor/*` GUI).** "메커니즘=엔진, 값=데이터"(GAME-DESIGN 8.6/8.8). (신규 프리미티브는 Rust에 — TS 오라클 은퇴, differential은 `archive/ts-core` 체크아웃)
- **실제 콘텐츠(런·캐릭터·스킬 수치·전직 트리·전투 배치)는 디자이너 영역 → 후순위.** 우리 일 = 디자이너가 GUI로 콘텐츠를 짤 수 있게 **엔진+에디터를 갖추는 것.**
- 로드맵 무게중심 = **새 엔진 프리미티브**(전직·종결모드) + **그 프리미티브를 데이터로 저작하는 에디터**.

## 🔑 가로지르는 선결 결정 — 콘텐츠 저작 형식 ✅ 확정 (2026-06: A, 점진적)

**결정: (A) 콘텐츠를 JSON으로 이주** — `content/<domain>/*.json`(또는 `<domain>.json`) + 타입드 로더(런 저작과 동일 패턴: dev-write 미들웨어 → JSON 기록 → 배럴/로더 → `data:export`). 에디터 인프라 재사용. **점진적 이주**(에디터 만드는 도메인만 그때그때 — jobs → items → skills → traits, `characters`는 TS 유지 후순위). TS+JSON 혼재는 이미 런(JSON)+나머지(TS)로 검증됨.
> (B) TS dev-write(에디터가 `.ts` 소스 생성/갱신, 파서/프린터)는 **기각** — erasable TS 제약 + 주석·포맷 왕복 보존이 악몽, A에 지배당함. 타입 안전성은 드리프트 가드 + 로드 검증으로 대체.
- **진행**: ✅ S-J1 jobs.ts → `jobs.json` + 로더(거동 무변, 번들 바이트 동일). ✅ S-J2 전직 트리 에디터(`editor/jobEditor.ts` + dev-write `/api/save-jobs` + 허브 진입). 다음 도메인 = ⑤-b 아이템(items.ts → JSON + 에디터).
