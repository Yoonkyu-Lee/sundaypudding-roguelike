# ROADMAP — 다음 작업 우선순위

이 문서 = **무엇을 다음에 만들지의 SoT.** 게임 규칙은 [`GAME-DESIGN.md`](GAME-DESIGN.md), 코드 위치는 [`CODE-MAP.md`](CODE-MAP.md). 각 항목은 진입 시 `/slice-plan`으로 분류하고, 끝나면 `/slice-wrap`이 이 문서의 상태를 갱신한다.

## 🧭 원칙 — 엔지니어는 엔진과 도구, 콘텐츠는 디자이너

- **우리(엔지니어)가 만드는 것 = ① 엔진 프리미티브(`engine/spr-core`) + ② 저작 도구(`web/src/ui/editor/*` GUI).** "메커니즘=엔진, 값=데이터"(GAME-DESIGN 8.6/8.8). (신규 프리미티브는 Rust에 — TS 오라클 은퇴, differential은 `archive/ts-core` 체크아웃)
- **실제 콘텐츠(캠페인·캐릭터·스킬 수치·전투 배치)는 디자이너 영역 → 후순위.** 우리가 할 일은 디자이너가 GUI로 콘텐츠를 짤 수 있게 **엔진+에디터를 갖추는 것.**
- 따라서 로드맵의 무게중심 = **새 엔진 프리미티브** + **그 프리미티브를 데이터로 저작하는 에디터**. 콘텐츠 제작은 도구가 준비된 뒤 디자이너에게.

## 🔑 가로지르는 선결 결정 — 콘텐츠 저작 형식 (에디터 확장의 전제)

현재 두 갈래다: **런/노드 = JSON**(에디터 드래프트 localStorage → `saveToRepo` dev-write → `data/runs/*.json`), **아이템·스킬·캐릭터·특성 = TS 모듈**(`data/items.ts`·`skills.ts`·`characters.ts`·`traits.ts`). 아이템/스킬/패시브를 GUI로 저작하려면 먼저 정해야 한다:

- **(A) 콘텐츠를 JSON으로 이주** — `data/*.json` + 런타임 로더(런 저작과 동일 패턴: 드래프트→dev-write→repo JSON). 에디터 인프라(store/saveToRepo) 재사용. **권장 후보.**
- **(B) TS 데이터에 dev-write** — 에디터가 `.ts` 소스를 직접 생성/갱신(파서/프린터 필요, erasable TS 제약). 복잡.
- 이 결정은 **방어구/무기/스킬/패시브 에디터 진입 전 `/slice-plan`에서 확정**한다. 메타 육성·연출 엔진은 이 결정과 독립(먼저 진행 가능).

## 📋 우선순위 (위→아래)

### 0. (선행) 게임 겉 구조 — 타이틀·본산·모드 → [`SHELL-DESIGN.md`](SHELL-DESIGN.md)
- 모드(캠페인/일반/챌린지)·본산 기지 골격을 먼저 확정한다. **메타 육성이 사는 그릇** — "무엇이 메타를 벌고 쓰나"가 모드에 매임. #1은 이 골격 위에서 진행.

### 1. 런 사이 메타 육성 (본산) — `[엔진 프리미티브 추가]` + 웹
- **목표**: 런↔런 사이 영구 성장 루프(장르 "육성형"의 심장). 메타 재화 획득 → 본산(home)에서 영구 해금/강화 → 다음 런이 강해짐.
- **현황**: 캐릭별 숙련도 XP/tier 해금만 있음(`web/meta.ts`, `spr_meta_v1`). 메타 재화·해금 트리·본산 화면·기술머신(5.3)은 **미구현**.
- **프리미티브 추정**: 메타 재화 자원(런 보상→메타 환전), 영구 해금 상태(캐릭/스킬/시작 보너스), 해금 조건/비용 스키마, 본산 화면. 결정론·세이브 분리(메타 vs 런) 유지. **갭 보고는 진입 시 `/slice-plan`.**
- **의존**: 없음(먼저 가능). 본산 = 허브(`web/hub.ts`) 확장 또는 신규 화면.
- **열린 질문**: 메타 재화 ↔ 런 골드 분리 원칙(GAME-DESIGN 5.2 "둘은 자원 공유 안 함") 준수. 해금 트리 데이터 스키마(디자이너 저작 대상 → 후속 에디터).

### 2. 연출 및 스토리텔링 엔진 — `[엔진 프리미티브 추가]` + 웹
- **목표**: 컷신·대사·연출을 데이터로 저작·재생. 야인시대 테마의 서사 표현.
- **현황**: 전투 중 `showDialog` 트리거 효과 + `text` 데코 레이어 + event 인카운터(제목/본문/선택지)는 있으나 **시각표현 최소**(텍스트 박스). 초상화·컷신 프레이밍·연출 시퀀스 없음.
- **프리미티브 추정**: 컷신/대사 시퀀스 스키마(화자·초상화·대사·연출 비트), 시퀀스 플레이어(맵/전투 양쪽), 초상화 에셋 참조. 기존 `showDialog`/event를 흡수·확장. 결정론(rng 시 state.rng).
- **의존**: 없음. 전투 오버레이(`web/battle/*`)·런 화면(`runRender`) 위에 연출 레이어.
- **열린 질문**: 컷신을 별도 노드 레이어로? event/트리거와 통합? 표시 수준(텍스트박스 vs 초상화 vs 풀연출) 단계적.

### 3. 지닌 물건 (held item) — `[엔진 프리미티브 추가]`(소) 또는 데이터
- **목표**: 잠겨 있는 3번째 장착 슬롯(지닌물건) 효과 정의 — 포켓몬 지닌물건류(조건부 발동·패시브 부여).
- **현황**: `EquipSlot: held` 슬롯은 있으나 **잠금**(`SLOT_NAME`엔 있음). `ItemDef`는 무기(dmgFlat·crit)·방어구(hp·shield)만 활용.
- **프리미티브 추정**: 지닌물건 효과를 **기존 패시브 룰 엔진(when/if/then)으로 표현 가능한지** 먼저 검토 — 가능하면 데이터-온리(아이템이 passives 부여), 불가면 소 엔진. **`/slice-plan`에서 판정.**
- **의존**: 패시브 엔진(이미 있음) 재사용 시 최소.

### 4. 저작 도구 확장 — 방어구·무기·스킬·패시브 에디터 — `[웹 기능]`
- **목표**: 노드 에디터처럼, 아이템(무기/방어구/지닌물건)·스킬·패시브/특성을 **GUI로 저작**(디자이너가 TS 안 만지게). "모든 콘텐츠는 데이터, 데이터는 GUI로"의 완성.
- **현황**: 맵/노드 에디터만 있음(`web/editor/*`). 아이템/스킬은 TS 직접 편집.
- **선결**: 위 "콘텐츠 저작 형식 (A) vs (B)" 결정. (A=JSON 이주 권장 시 store/saveToRepo 재사용.)
- **순서 제안**: ④-a 아이템 에디터(무기/방어구/지닌물건 — `ItemDef` 스키마, 가장 단순) → ④-b 스킬 에디터(`Skill`+effect/area/reach/타겟마스크) → ④-c 패시브/특성 에디터(when/if/then — `ruleEditor` 패턴 재사용 가능). 스키마 구동 폼(`layerSchema`/`ruleSchema` 패턴) 확장.
- **의존**: 저작 형식 결정. 패시브 에디터는 노드 트리거 룰 에디터(`ruleEditor.ts`) 재사용.

## ⏳ 후순위 (디자이너 영역 / 튜닝 / 후속)

- **실제 콘텐츠 — 캠페인·캐릭터·적·스킬셋**: 위 도구가 준비되면 **디자이너가 GUI로 제작**. 엔지니어 후순위.
- **적 AI 프로파일 배정**: 엔진(`ai/profile.ts`)·스키마는 있음 → `data/ai.ts`에 프로파일 작성 + 캐릭 `aiProfileId` 배정 = **데이터-온리**(콘텐츠).
- **밸런스 패스**: DoT 스택뎀·보유 스킬 상한·행동수치 상수 등 placeholder 확정(부록 B). 콘텐츠 채워진 뒤 튜닝.
- **모드**: 캠페인(1:多)·일반(多:多) 규칙·모드 선택 UI(7.4).
- **적 스탯 층 스케일링 · 웹 렌더러 고도화**.
