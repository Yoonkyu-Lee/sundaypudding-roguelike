# NODE-DESIGN.md — 노드 내부 설계 회의 (진행 중)

> **목적**: 맵 노드의 "내부 내용물"을 상세 설계한다. 게임 아이디어 회의를 위에 기록하고, 결론이
> 나오면 **하단에 개발 구현 플랜(슬라이스)**을 적는다. 실제 구현은 `/slice-plan`으로 진행.
> **상태**: 브레인스토밍 중(미확정 다수). 확정된 규칙은 추후 `docs/GAME-DESIGN.md`로 승격, 코드 매핑은 `docs/CODE-MAP.md`.
>
> 회의 주제 3개: ① 어떤 노드를 추가할지 ② 각 노드의 정형화된 내용물(전역 vs exclusive) ③ 디자이너용 노드 내용물 GUI.

## 0. 현재 상태 (grounding) — 코드 기준 노드별 내용물

| 노드 | 현재 내용물 | 엔진 vs 데이터 |
|---|---|---|
| **입장(start)** | 층 진입점. 내용 없음(`entryNodeId`) | — |
| **전투(battle)** | 적과 전투. 승리 시 +8G + 보상 3택1 | 적 구성=데이터(`NODE_ROSTERS.battle` 또는 `MapNode.roster`) |
| **엘리트(elite)** | 전투. 승리 시 +16G + 보상 3택1 | **엔진 차이 0** (battle과 동일 메커니즘). 적 구성·골드만 다름 |
| **보스(boss)** | 전투. **적 진형 보너스 활성**(6.3). 승리 시 +24G + 보상 3택1. "길목"(층 종료는 clear가) | 엔진: `enc.boss`→`enemyFormation`. 적 구성=데이터 |
| **상점(shop)** | 진열: 강화권 25G · 범용기 학습 20G · 아이템 2종 · 회복(50%) 15G | 진열 생성 로직=엔진(`shop.ts`), 가격 하드코딩 |
| **휴식(rest)** | 즉시 부활 + 파티 50% 회복 | 엔진 하드코딩(`healParty(0.5,true)`) |
| **인카운터(encounter)** | 전역 풀(`ENCOUNTER_EVENTS`)에서 **랜덤** 1개 → 선택지/도박(회복·피해·골드·강화·학습) | 이벤트=데이터(`data/events.ts`), 추첨=엔진 |
| **클리어(clear)** | 진입 시 층 종료 → `toFloor`(없으면 승리) | `toFloor`=데이터 |

**현재 약점(이번 회의 동기):**
- 노드 "커스텀"이 거의 없음 — 에디터에서 전투 노드의 적 구성/배치 + 라벨만 편집 가능. 그 외 내용물은 타입에 고정.
- **엘리트가 전투와 메커니즘적으로 동일**(적·골드만 다름). 보상 품질은 타입 무관(`genRewards`가 타입 안 봄).
- 인카운터는 **노드별 저작 불가**(전역 풀에서 랜덤). 특정 노드에 특정 이벤트를 못 박음.
- 골드·회복량 등 값이 엔진에 하드코딩(데이터/엔진 경계 위반 소지).
- 진입 연출/스토리/배경 등 "분위기" 레이어 부재.

## 1. 토론: 어떤 노드(코어)를 둘지

**관점 전환(결정 1·4의 귀결)**: "노드 종류" = **코어 아키타입**(중심 상호작용 modality). 다양성은 코어 종류 난립이 아니라 **코어 파라미터 + 레이어 + 프리셋**에서 나온다.

**확정**:
- **결정 4 (전투 통일)**: `battle/elite/boss` 타입 폐기 → **`combat` 코어 1개** + 편집 필드(적 구성·진형 보너스 on/off·골드·보상 등급·웨이브). **엘리트/보스 = 이 코어의 프리셋(데이터 값)**. 엘리트 메커니즘-0-차이 약점 해소.

**★ 모델 정련 (결정 5) — "코어"의 일반화**: 디자이너 통찰("레이어가 미니게임 같은 상호작용 모듈도 될 수 있다면 코어=가장 무거운 레이어 아닌가?")에 따라 모델을 일반화한다:

> **노드 = 순서 있는 레이어 리스트.** 레이어 종류 = 카탈로그(2갈래):
> - **상호작용 모듈**(완료까지 블록 — "무엇을 하는가"): combat · event(선택지) · shop · rest · *미니게임류(지뢰찾기·탄막·횡스크롤 = 미래 플러그인)* …
> - **데코레이터**(즉시 실행): 컷신/대사 · 보상 부여 · 골드± · 상태부여 · 배경/BGM …
> - + **트리거 룰**(결정 2b/3): 진행 *도중* 반응(전투 중 대사 등) = when/if/then.

**역할 분담**:
- **엔지니어**: ① 레이어 **호스트**(시퀀서 + 인터페이스: 띄우기→완료신호→다음, 런/전투 상태 연동) ② 각 **레이어 종류 모듈** ③ 종류별 **편집 스키마**. 새 종류 추가 = 모듈+스키마 등록(호스트 불변).
- **디자이너**: 레이어 종류 선택 + 편집 콘텐츠(스토리·보상풀·강화풀·적 구성…) 채우기 + **순서 배치**.
- "오락 노드" = 미니게임 레이어 + 보상 레이어 조합(프리셋). "엘리트" = combat 레이어(진형보너스 on, 보상등급↑) 프리셋.

**YAGNI 경계**: 지금 설계 = **레이어 프레임워크**(호스트·인터페이스·순서·스키마·GUI). 무거운 모듈(미니게임)은 **미래 플러그인** — 끼울 수 있게만.

**신규로 원하는 내용물(사용자 선택)**: treasure(비전투 보상) · event(인카운터 일반화+노드별 저작+컷신/대사) · forge(강화 전담) · shrine(영구 업그레이드/저주 대가) · (장기) 오락/미니게임. → 일부는 독립 레이어 종류, 일부는 event/shop의 **프리셋/변형**으로 실현(아래 Q에서 분류).
**결정 6 (v1 범위)**: v1 레이어 종류 =
- **상호작용**(기존 코드 레이어화): `combat` · `event`(인카운터 일반화) · `shop` · `rest`.
- **데코레이터**(신규 소형): `dialog/cutscene`(showDialog) · `grantReward`(보상풀) · `gold±` · `applyStatus` · `background/bgm`.
- **프리셋/변형**: treasure = `grantReward` 단독 노드 · forge = `shop`(강화 전담 진열) 프리셋 · shrine = `event`(영구 업그레이드/대가) 프리셋. elite/boss = `combat` 프리셋.
- **미래 플러그인**(v1 제외, 확장점만): 미니게임류(지뢰찾기·탄막·횡스크롤), 오락 노드.

## 2. 토론: 각 노드의 정형화된 내용물 (전역 레이어 vs 타입 exclusive)

**확정 모델 = 레이어 + 타입 코어** (결정 1):
- 모든 노드 = **공통 레이어들**(어디든 부착 가능) + **타입 고유 코어 1개**(그 노드가 "무엇을 하는가").
- 공통 레이어 = 진입 연출·도착 보상·배경/BGM·등장 대사 등 타입 무관 부착물.
- 코어 = 전투/상점/휴식/인카운터/… 의 핵심 상호작용. 코어 종류 = "어떤 노드를 만들지"(토론 1)와 동일 축.
- 엔진 해석 순서: **pre-레이어(onEnter) → 코어(core) → post-레이어(onResolve)**.
- 데이터/엔진 경계: 레이어·코어 종류 = 프리미티브(엔진 해석), 그 안의 값 = 데이터.

**생애주기 골격 = 3슬롯 (항상 존재, 결정 2a)**: **onEnter**(진입) · **core**(콘텐츠) · **onResolve**(종료). 어떤 노드든 보장되는 규격.

**자유 레이어 = 트리거 룰 (parameterizable, 결정 2b)**: 디자이너가 노드에 `{when·if·then}` 룰을 **자유롭게 추가**. onEnter/onResolve는 흔한 `when` 트리거일 뿐이고, **코어 진행 도중 이벤트**(전투: 라운드 시작·특정 유닛 HP 이하·N턴·등)에도 반응 가능.
- 예시(사용자 제시): "전투 중간 특정 조건마다 대사" = `when: round(N) → then: [dialog]`; "비전투 인물이 전투에 상태이상 개입" = `when: 조건 → then: [applyStatus(난입자)]`.
- **이건 기존 패시브/특성 엔진과 동형**(`PassiveRule = {when:Trigger, if:Condition[], then:Effect[]}`, `combat/passives/*` + 런스코프 `nodeEnter`). → 재사용 후보(아래 토론).

```
MapNode {
  core: { kind, ...코어별 스키마 }       // 타입 고유
  rules: NodeRule[]                       // 자유 레이어 {when, if, then}
  // onEnter/onResolve = rules 중 흔한 when 프리셋(GUI 버킷)
}
```
> _세부(자유 레이어 구현 메커니즘·레이어 카탈로그·코어별 스키마) 진행 중._

## 3. 토론: 디자이너용 노드 내용물 디자인 GUI

**결정 7 (GUI 구조)**: **전용 노드 에디터** — 맵 에디터에서 노드 더블클릭 → 전용 화면. 왼쪽 = 레이어 리스트(순서 드래그·추가/삭제·온엔터/코어/온리졸브 버킷), 중앙 = 선택 레이어 편집 폼, 하단 = 트리거 룰 편집. 복잡한 레이어(전투 4×4 배치·이벤트 선택지)도 충분한 공간. 기존 우측 사이드바(`nodePanel`)는 빠른 요약만.
**결정 8 (폼 렌더)**: **스키마 구동 + 리치 에디터 하이브리드**. 레이어 종류마다 필드 스키마 등록 → 단순 필드(숫자·텍스트·선택·토글·풀 선택)는 폼 제너레이터가 자동 생성. 복잡 위젯(전투 4×4 배치·이벤트 선택지 트리)만 종류별 **리치 에디터 컴포넌트** 등록(기존 `nodePanel` roster 에디터 재사용). 새 레이어 = 스키마 등록만으로 폼 공짜, 리치는 컴포넌트 추가.

```
registerLayer("combat", { schema:[{roster:'rosterGrid'},{formationBonus:'bool'},{gold:'int'},{rewardTier:'enum'}] })
// 단순 필드 → 자동 폼 / 'rosterGrid' 같은 리치 위젯만 커스텀 등록
```

## 결정 로그 (확정 사항 누적)
- **결정 1 (노드 모델)**: 레이어 + 타입 코어. 노드 = 공통 레이어(진입 연출·보상·배경 등) + 타입 고유 코어 1개. 엔진은 pre→core→post 순서로 해석. (현행 "타입 고정" 대비 진입 컷신 등 횡단 기능을 데이터로 부착 가능.)
- **결정 2a (생애주기 골격)**: 3슬롯 onEnter·core·onResolve 항상 존재(보장 규격).
- **결정 2b (자유 레이어)**: 디자이너가 `{when·if·then}` 트리거 룰을 자유 추가. 코어 진행 도중 이벤트(전투 라운드/HP/턴 등)에도 반응. onEnter/onResolve는 흔한 when 프리셋.
- **결정 3 (레이어 구현)**: **기존 트리거 엔진 재사용**(`PassiveRule {when,if,then}` + `combat/passives/*` + 런스코프). 노드 룰을 전투 시작 시 "내레이션 룰 소스"로 주입 → 기존 디스패치 발동. 대사·난입 연출만 **새 Effect**(`showDialog`/`intervene`) 추가. 특성·스킬과 같은 언어 공유.
- **결정 4 (전투 코어 통일)**: `battle/elite/boss` 폐기 → `combat` 코어 1개 + 편집 필드(적·진형보너스·골드·보상등급·웨이브). 엘리트/보스 = 프리셋 데이터.
- **결정 5 (모델 정련: 레이어 컴포지션)**: 노드 = **순서 있는 레이어 리스트**. 레이어 = 상호작용 모듈(combat/event/shop/rest/미니게임) + 데코레이터(컷신·보상·골드·상태·배경) + 트리거 룰. 엔지니어=호스트+모듈+스키마, 디자이너=선택·편집·순서. "코어"는 가장 무거운 레이어의 별칭. 미니게임 등 무거운 모듈은 미래 플러그인(확장점만 확보).
- **결정 6 (v1 범위)**: 상호작용 combat·event·shop·rest(기존 레이어화) + 데코 dialog·grantReward·gold·applyStatus·background. treasure/forge/shrine/elite/boss=프리셋. 미니게임=확장점만(제외).
- **결정 7 (GUI)**: 전용 노드 에디터(더블클릭→화면): 레이어 리스트(순서·추가/삭제) + 선택 레이어 폼 + 트리거 룰.
- **결정 8 (폼 렌더)**: 스키마 구동 자동 폼 + 리치 위젯(roster/선택지)만 커스텀 컴포넌트. 새 레이어=스키마 등록.

## 구현 플랜 (슬라이스)

> **규모**: 이건 단일 슬라이스가 아니라 **에픽**(맵 노드 엔진 재구성). 단계(Phase)별로 묶고, 각 Phase 안에서 `/slice-plan`으로 슬라이스 단위 실행. 분류 표기: `[엔진 프리미티브 추가]` / `[데이터-온리]` / `[웹 기능]`.
> **불변 유지**: 결정론·코어 순수성·이벤트 로그 구동·기존 테스트 green. 매 슬라이스 데모 골든 영향 없음(데모=단일 전투).

### Phase A — 레이어 프레임워크 골격 (엔진) `[엔진 프리미티브 추가]`
가장 위험하고 기반이 되는 부분. 거동 보존(기존 노드를 레이어로 감싸 동일하게).

### Phase B — combat 통일 + 데코레이터 레이어 `[엔진 프리미티브 추가]`+`[데이터-온리]`

- **B2. 데코레이터 레이어**: `grantReward`(보상풀)·`gold±`·`applyStatus`·`background/bgm`. 기존 healParty/보상 로직 재사용. treasure = `grantReward` 단독 노드.
- **B3. 프리셋**: forge=`shop`(강화 전담) 프리셋, shrine=`event` 프리셋(B/Phase D 의존).

### Phase C — 스토리텔링: dialog 레이어 + 노드 트리거 룰 `[엔진 프리미티브 추가]`
- **C1. dialog/cutscene 레이어 + 뷰**: `showDialog` 데코레이터 + 웹 표시(대사/컷신 오버레이). 최소 스토리텔링 표시 엔진(텍스트·화자·선택 없는 연출).
- **C2. 노드 트리거 룰**: 노드 `rules`(when/if/then)를 전투 시작 시 "내레이션 룰 소스"로 주입 → 기존 `combat/passives` 디스패치 발동. 새 Effect `intervene`(비전투자 효과)·`showDialog`(전투 중 대사). 결정론 테스트.

### Phase D — event 레이어 일반화 `[엔진 프리미티브 추가]`+`[데이터-온리]`
- **D1. event 레이어**: 인카운터를 "선택지→결과" 레이어로 일반화 + **노드별 저작**(랜덤 대신 특정 이벤트/선택지 인라인). 기존 `ENCOUNTER_EVENTS`는 풀 프리셋으로.
- **D2. shrine 프리셋** + 선택지에 컷신/조건 연결.

### Phase E — 전용 노드 에디터 GUI `[웹 기능]` (각 Phase와 평행)
> 평행 개발 원칙: 레이어 종류가 엔진에 생길 때마다 GUI도 같이. 아래는 GUI 자체의 뼈대.
- **E1. 노드 에디터 화면**: 더블클릭 진입, 레이어 리스트(순서 드래그·추가/삭제 — 기존 `drag.ts`/`camera` 패턴 재사용), 빈 폼 영역.
- **E2. 스키마 구동 폼 제너레이터**: 레이어 kind별 필드 스키마 → 자동 폼(숫자·텍스트·토글·enum·풀 선택).
- **E3. 리치 에디터 등록**: roster 4×4(기존 `nodePanel` 재사용)·이벤트 선택지 트리.

### 권장 순서
