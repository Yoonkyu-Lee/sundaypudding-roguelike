## 0. 북극성 (설계 기준)

> **"다키스트 던전의 반대 — 매뉴얼을 읽는 게임이 아니라, 몇 번 부딪히면 몸으로 아는 게임.
> 포켓몬 전투만큼 직관적인 육성형 로그라이크."**

모든 설계 결정은 이 한 문장으로 검증한다: **"이게 더 직관적인가? 읽지 않고 보면 아는가?"**

다키스트 던전이 무거웠던 근본 원인은 **숨은 수치와 숨은 계산**이었다. 우리는 이를 두 축으로 제거한다:
1. **계산을 없앤다** — 데미지는 상수, 능력치 연산 최소화.
2. **변형을 까발린다** — 모든 보정은 `원본 → 현재`로 화면에 병기.

### 0.1 대원칙: 엔진은 일반형, 모드는 제한된 설정

> **엔진은 가장 일반적인(maximal) 경우를 구현한다. 각 게임 모드는 그 일반 엔진을 "설정으로 제한"한 것이다.**

- 깊이(다키스트식 위치/포메이션)는 **엔진의 일반성**에서 나온다.
- 직관성(포켓몬식 단순함)은 **기본 모드의 제한된 설정**에서 나온다.
- 그래서 "직관 vs 깊이"는 충돌하지 않는다. 둘 다 가진다.

예시: 전체 위치 시스템을 구현해두고 "1행만" 설정 → 단순 모드 / 턴서열을 모듈로 분리해
라운드제·스타레일식을 갈아끼움 / 적 슬롯 4→5는 파라미터.

### 0.2 수치 투명성 원칙

- 모든 능력치·데미지는 **절대불변 고정값이 아니다.** 성장/버프/디버프/특수효과가 언제든 보정한다.
- 보정이 걸리면 화면엔 **`원본 → 현재`** 로 병기한다. (예: 데미지 `30 → 45`, 회피 `20 → 35`)
- 플레이어가 **상태창을 펼쳐 직접 계산할 일이 없어야** 한다. 필요한 결과 수치는 그 순간 그 자리에 뜬다.

## 1. 장르 정의

| 항목 | 결정 | 상태 |
|---|---|---|
| 대장르 | **육성형 로그라이크** | ✓ |
| 덱빌딩 | **제외** (읽을거리가 너무 많아 북극성 위반) | ✓ |
| 멘탈 모델 | **포켓몬 배틀**(1턴 1행동, 유닛당 스킬 4개) **+ 진형식 위치 전투** | ✓ |

**육성형 로그라이크란?** 캐릭터(사람)를 **영구히 키워서** 보유하고, 매 출격마다 그중 일부를
파티로 편성해 연속 전투를 돌파한다. 캐릭터의 성장은 판과 판 사이에 **남는다**(메타 진행 = 로그라이트의 "기억 회랑/계승").

핵심 재미 루프:
```
캐릭 키운다 → 파티 짠다 → 출격해 시험한다 → 배운 걸로 더 잘 키운다 → 다시 출격
```
