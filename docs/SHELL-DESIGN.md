# SHELL-DESIGN.md — 게임 겉 구조 회의 (진행 중)

> **목적**: 게임의 **바깥 틀**을 설계한다 — 타이틀 → (디자이너 진입점들 + Start) → **본산 기지** → **모드(캠페인/일반/챌린지)** → 런. 회의 기록을 위에, 결론은 결정 로그 + 구현 플랜에.
> **상태**: 브레인스토밍 중(🔸=제안/미확정). 확정 규칙은 `GAME-DESIGN.md`로 승격, 코드 위치는 `CODE-MAP.md`, 우선순위는 `ROADMAP.md`.
> **관련**: 노드 내부 설계 = [`NODE-DESIGN.md`](NODE-DESIGN.md). 다음 작업 우선순위 = [`ROADMAP.md`](ROADMAP.md).

## 0. 현재 상태 (grounding) — 곧 대체될 화면

- **타이틀**(`shell.ts`): `▶ 시작` + `🗺 런 에디터`(디자이너 진입점) + 부제(제거됨).
- **Start → 허브**(`hub.ts`): 플레이어블 풀에서 **로스터 1~4 자유 편성**(영구저장) + **런 목록(repo+드래프트)에서 1개 선택** → 플레이. 로스터는 전역, `useMastery`만 RunDef별. 숙련도 XP는 자동 획득(소비 화면 없음 = 임시).
- **모드 개념 없음** → 이 화면 전체를 **본산 기지 + 모드 구조로 대체**한다.
- 엔진 기보유: 다층 `RunDef`(층 그래프)·`createRun`·숙련도(`spr_meta_v1`)·런 에디터. **모드/본산/메타소비/난이도사다리/스토리게이트는 미구현.**

## 1. 확정 결정

- **D1 — 기지 허브(B형) 채택**: 미니멀 허브가 아니라 **런 사이 영구 투자형 기지**(Hades 집·Darkest Dungeon 마을격). "육성형" 정체성 + 로드맵 #1(본산 메타 육성)의 그릇.
- **D2 — 모드 = 런 위 최상위 컨테이너**: 런이 원자, 모드가 "교전 규칙"(어떤 런·로스터 규칙·연속성·메타 결합·연출). **`ModeDef` 데이터 프리미티브**로 디자이너 저작(런 에디터 철학 일관).
- **D3 — 타이틀 = Start + 디자이너 진입점 나열**: 런 에디터처럼 스킬/캐릭터/아이템 에디터 등 **디자이너 도구 진입점**을 타이틀에 나열(플레이어 진입점 = Start 하나).
- **D4 — 흐름**: `타이틀 → Start → 본산 기지 → 모드 선택(캠페인/일반/챌린지) → 런`. 본산이 중심 화면(메타 소비·다이브 출발점).
- **D5 — 일반 모드 = "레전드 스토리 포지션"**: 저작 런 풀(디자이너 양산) + 난이도/보상 사다리. **메타 주 수입원·플레이타임 대부분.**
- **D6 — 세 모드 = 냥코 대응**: 캠페인(세계/미래/우주편: 스토리·해금 게이트) · 일반(레전드 스토리: 그라인드) · 챌린지(냥코 도장: 단일 리니어 런 기록).

## 2. 화면 흐름 골격

```
타이틀
 ├─ ▶ Start ──────────────→ 본산 기지 ──→ [모드 선택] ──→ 런 플레이 ──(보상)──┐
 │                              ↑  ↑                                          │
 │                              └──┴──── 메타 재화 소비·캐릭터 육성·해금 ←─────┘
 └─ 디자이너 진입점: 🗺 런 에디터 · (예정) 스킬 에디터 · 캐릭터 에디터 · 아이템 에디터 …
```
- **본산 기지** = 메타 루프의 중심: 메타 재화 소비(영구 육성/해금) + 로스터 관리 + 모드 진입.
- 메타 루프: `런에서 재화·드롭·XP 획득 → 본산서 영구 투자 → 더 강해져(또는 더 어렵게) 다시 다이브`.

## 3. 모드별 법칙 (🔸 제안 — 토론 중)

| 축 | 🔸 캠페인 (1:多) | 🔸 일반 (多:多) | 🔸 챌린지 (도장격) |
|---|---|---|---|
| **런 제공** | 저작 챕터 시퀀스(고정 순서) | 저작 런 **풀**(다수, 자유/해금 선택) | 단일 리니어 런(고정 층/노드) |
| **로스터** | 제한(캠페인별 허용 풀/고정) | **자유 편성**(현재 허브) | 자유 또는 고정(기록 공정성) |
| **연속성/계승** | 챕터 클리어=다음 해금. 빌드는 런 단위 리셋 | 런 독립. 메타(육성·재화·드롭)만 영구 | 1회성, 영구 보상 없음/극소 |
| **난이도** | 저작 고정 | **난이도 사다리**(승천/Heat格 — 더 어렵게=더 좋은 보상) | 갈수록 어려워지는 단일 건틀릿 |
| **보상·메타** | 해금(캐릭/런/모드/스토리), 메타 소량 | **메타 주 수입**(재화·XP·드롭) | 거의 없음 — **기록(도달 깊이)**이 보상 |
| **연출** | 강(서사·컷신) | 약 | 무 |
| **반복성** | 낮음(1회 클리어 목적) | 높음(플레이타임 대부분) | 높음(기록 경신) |
| **게이팅** | 클리어가 타 콘텐츠 해금 | 대부분 처음부터 열림 | 독립 |
| **냥코 대응** | 세계/미래/우주편 | 레전드 스토리 | 냥코 도장 |
| **로그라이크 레퍼런스** | Hades 서사·DD 챕터 | StS 승천·Hades Heat·DD 원정 그라인드 | StS 데일리·끝없는 모드·기록 |

## 4. 가로지르는 열린 질문 (🔸 토론)

- **Q1 — 무엇이 영구 계승되나?** (사용자: "영구 계승은 극히 제한적".) 🔸 후보: **캐릭터 해금**(영구) + **숙련도 레벨/tier**(영구, 이미 있음) + **소형 본산 업그레이드**(?) — 단, **빌드·아이템·골드는 런 리셋**(로그라이크 유지). 어디까지?
- **Q2 — 메타 재화의 원천/용처?** 🔸 일반 모드가 주 수입 → 본산서 소비. 용처 = 캐릭터 해금·영구 강화 트리·시작 보너스 중 무엇? (Q1과 연동)
- **Q3 — 게이팅 그래프?** 🔸 캠페인 클리어 → 일반/챌린지/캐릭터 해금? 아니면 전부 처음부터? (냥코: 세계편 진행이 미래편·일부 캐릭 해금)
- **Q4 — 일반 모드 난이도 사다리 형태?** 🔸 런별 승천 단계(StS) vs 전역 Heat(Hades) vs 런 풀 자체가 난이도 티어. 보상 스케일과 결합.
- **Q5 — 챌린지 = 단일 도장 런(냥코) vs 일반 런들의 승천 모드(Hades)?** 둘은 다름. 🔸 v1은 "전용 도장 런 + 기록"으로 단순하게?

## 5. 데이터 프리미티브 초안 (🔸 — 엔진 변경, 추후 `/slice-plan` 승인)

모드 자체를 디자이너가 저작(런 에디터 철학). 🔸 형태 후보:
- `CampaignDef = { id, name, chapters: { runId, story?, unlockOnClear? }[], rosterRule }`
- `NormalPool = { runs: runId[] | "all", ascension? }` (또는 런별 난이도 티어)
- `ChallengeDef = { runId, scoring, modifiers? }`
- 공통 `ModeRef`로 본산이 나열. **(미확정 — Q1~Q5 정리 후 스키마 확정.)**

## 6. 디자이너 진입점 (타이틀)

## 결정 로그
- **D1** 기지 허브(B형). **D2** 모드=런 위 최상위 컨테이너(ModeDef 데이터). **D3** 타이틀=Start+디자이너 진입점 나열. **D4** 흐름 타이틀→본산→모드→런. **D5** 일반=레전드 스토리 포지션(저작 런 풀+난이도 사다리, 메타 주 수입). **D6** 3모드=냥코 세계편/레전드/도장 대응.

## 구현 순서 메모
- 본 문서 = **겉 구조의 SoT**. 확정되면 ROADMAP #1(본산 메타 육성)이 이 골격 위에서 진행 — 모드 골격을 메타보다 먼저/함께 잡는 이유: "무엇이 메타를 벌고 쓰나"가 모드에 매여 있음.
- 각 슬라이스는 `/slice-plan`. 모드/본산 = `[엔진 프리미티브 추가]`+웹 큰 슬라이스.
