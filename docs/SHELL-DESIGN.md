## 0. 모델 요약 (인터뷰 종합)

- **모든 런은 0(최초 상태)에서 시작 → 끝나면 전부 리셋.** 빌드·전직·아이템·골드는 런 안에서만. **런 그 자체가 가장 중요**(지속성과 직결, Q16).
- **본산 영구 투자·메타 재화 = 없음**(의도된 미니멀). 영구 성장 = **숙련도→스킬풀 확장 하나**(상한 有, Q1/Q5). 캐릭/런/난이도는 **비-재화 진행 해금**(Q17).
- **롱텀 동력 (Q12):** ① 빌드 실험(스킬풀×전직) ② 난이도 숙달·기록(종결 모드) ③ 캠페인 서사(후순위).
- 따라서 셸은 **얇다**: 본산 같은 메타 허브가 아니라 **런 목록 + 로스터 편성 + (미니멀) 숙련도 + 모드 진입**.

## 1. 현재 상태 (grounding) — 대체될 화면

- **타이틀**(`web/src/ui/shell.ts`): `▶ 시작` + `🗺 런 에디터`(디자이너 진입점).
- **Start → 허브**(`web/src/ui/hub.ts`): 플레이어블 풀에서 **로스터 1~4 자유 편성**(영구저장) + **런 목록(repo+드래프트)에서 1개 선택** → 플레이. 로스터는 전역, `useMastery`만 RunDef별. 숙련도 XP는 자동 획득(소비/표시 화면 없음 = 임시, `web/src/ui/meta.ts` `spr_meta_v1`).
- **모드 개념 없음** → 이 화면을 **모드 선택 + 런 중심 구조로 정리**한다(본산은 만들지 않음).
- 엔진 기보유: 다층 `RunDef`(층 그래프)·`createRun`·숙련도·런 에디터. **모드 컨테이너/난이도 사다리/종결 모드/진행 해금/숙련도 소비 화면은 미구현.**

## 2. 확정 결정

- **D1 — 본산 폐기, 셸은 얇게.** 런 사이 영구 투자형 기지 **만들지 않음**(디자이너가 원치 않음). 셸 = 타이틀 → Start → 모드/런 선택 → 런. 메타 소비 화면 없음.
- **D2 — 런이 원자, 모드는 얇은 컨테이너.** 모드는 "어떤 런 풀·로스터 규칙·길이·해금/난이도 결합"만 정의. **`ModeDef` 데이터 프리미티브**로 디자이너 저작(런 에디터 철학 일관) — 단 메타 결합 행은 없음.
- **D3 — 타이틀 = Start + 디자이너 진입점 나열.** 런 에디터처럼 스킬/캐릭터/아이템 에디터 등 **디자이너 도구 진입점**을 타이틀에 나열(플레이어 진입점 = Start 하나). (메타와 무관 — 유지.)
- **D4 — 흐름**: `타이틀 → Start → 모드 선택 → (런 선택 + 로스터 편성) → 런`. 중심 화면 = **런 선택**(본산 아님).
- **D5 — 영구 계승 = 숙련도→스킬풀 하나 + 해금.** 빌드·아이템·골드·전직은 런 리셋(로그라이크 유지). 숙련도는 상한 있는 미니멀 축. 캐릭/런/난이도 해금은 진행으로(비-재화).
- **D6 — 3모드 (런 중심 재정의)**: **기본**(20~30분 저작 런 풀 — 빌드 실험의 무대, 1순위) · **종결·지속**(정통 로그라이크, 긴 런·난이도 사다리·기록, **처음부터 오픈**, 2순위) · **캠페인**(서사 챕터, 후순위·정기 추가, 3순위).

## 3. 화면 흐름 골격

```
타이틀
 ├─ ▶ Start ──→ [모드 선택] ──→ 런 선택 + 로스터 편성 ──→ 런 플레이 ──(클리어)──→ 진행 해금
 │                  │              ↑ (미니멀) 숙련도/스킬풀 화면                      │
 │                  └──────────────────────── 해금된 런/캐릭/난이도가 다음에 열림 ←──┘
 └─ 디자이너 진입점: 🗺 런 에디터 · (예정) 스킬 · 캐릭터 · 아이템 · 전직 트리 에디터 …
```
- **본산 없음.** 메타 루프 대신 **진행 해금 루프**: `런 클리어 → 캐릭/런/난이도 해금 + 출전 캐릭 숙련도 적립 → 더 넓은 풀·더 깊은 난이도로 다음 런`.
- 빌드·골드·아이템·전직은 **런 내부**에서 살고 끝나면 사라짐.

## 4. 모드별 법칙 (🔸 제안 — 토론 중)

| 축 | 🔸 기본 (런 풀) | 🔸 종결·지속 (정통 로그라이크) | 🔸 캠페인 (서사·후순위) |
|---|---|---|---|
| **런 제공** | 저작 런 **풀**(다수, 해금 선택) | 긴 런 / 난이도 사다리(끝없거나 깊은) | 저작 챕터 시퀀스(고정 순서) |
| **로스터** | **자유 편성**(현재 허브) | 자유(또는 기록 공정성용 고정) | 제한(챕터별 허용 풀/고정) |
| **길이** | 20~30분 (Q19) | 길게 1시간+ ("성장 뽕맛", Q19) | 챕터 단위 |
| **빌드/전직** | 런 단위(매번 0→리셋), 전직으로 다양화 | 동일 + 더 깊은 빌드 지속 | 런 단위 |
| **영구** | 숙련도 적립 + 진행 해금 | 숙련도 적립 + **기록(도달 깊이)** | 해금(캐릭/런/스토리) |
| **난이도** | 저작/완만 | **난이도 사다리**(더 어렵게=더 깊이) | 저작 고정 |
| **연출** | 약 | 무 | 강(서사·컷신) |
| **게이팅** | 진행 해금(클리어가 다음 엶) | **처음부터 오픈**(클리어 무관, Q17) | 클리어가 다음 챕터/콘텐츠 해금 |
| **반복성** | 높음(플레이타임 대부분, 빌드 실험) | 높음(기록 경신·뽕맛) | 낮음(1회 클리어 목적) |
| **레퍼런스** | StS 일반 런 | StS 승천/끝없는 모드·기록 | 서사형 챕터 |

## 5. 가로지르는 열린 질문 (🔸 토론)

- **Q1 — 기본 vs 종결 모드의 런 구조 차이?** 🔸 기본 = 짧은 저작 런 풀, 종결 = 긴 런 + 난이도 사다리(또는 끝없음). 둘이 별도 런인가, 같은 런의 난이도 변주인가?
- **Q2 — 난이도 사다리 형태?** 🔸 런별 승천 단계(StS) vs 전역 단계 vs 런 풀 자체가 난이도 티어. 보상/깊이와 결합. (종결 모드의 핵심.)
- **Q3 — 진행 해금 그래프?** 🔸 무엇이 무엇을 여나 — 기본 런 클리어 → 캐릭/런/난이도 해금? 종결 모드만 처음부터 오픈(Q17). 구체 게이팅 TBD.
- **Q4 — 로스터 편성이 모드별로 다른가?** 🔸 기본 = 자유, 종결 = 자유/고정, 캠페인 = 제한. (현재 허브 = 전역 자유 편성.)
- **Q5 — 전직 가용성은 모드/런이 정하나?** 🔸 기본값 = 모든 런에 전직 노드. 모드/런이 끄거나 인원 캡을 조절? (전직 자체 설계 = ROADMAP #1 / NODE-DESIGN.)

## 6. 데이터 프리미티브 초안 (🔸 — 엔진 변경, 추후 `/slice-plan` 승인)

모드 자체를 디자이너가 저작(런 에디터 철학). **메타 재화 결합 없음.** 🔸 형태 후보:
- `ModeDef = { id, name, kind: "basic"|"endless"|"campaign", runs: runId[] | "all", unlock?, difficulty? }` — 얇은 컨테이너.
- `BasicPool = { runs: runId[], unlockGraph? }` (해금 그래프).
- `EndlessDef = { baseRunId | poolId, difficultyLadder, scoring }` (종결·지속, 기록).
- `CampaignDef = { chapters: { runId, story?, unlockOnClear? }[], rosterRule }` (후순위).
- 공통 `ModeRef`로 모드 선택 화면이 나열. **(미확정 — § 5 Q1~Q5 정리 후 스키마 확정.)**
