# 게임 시스템 명세서 (작업 제목: *Sundaypudding Roguelike*)

> 이 문서는 **공략집/나무위키형 시스템 명세**다. "이 게임의 시스템이 어떻게 동작하는가"를
> 에셋·스토리 없이 **규칙 레벨로** 서술한다. 구현(자체 엔진)은 이 문서를 진실의 원천(source of truth)으로 삼는다.
>
> 작성 방식: 디렉터(Claude) ↔ 기획자(사용자)의 grill-me 인터뷰로 한 칸씩 확정해 나간다.
> 상태 범례: `✓ 확정` · `★ 차별화 후보` · `☐ 미정/후속 인터뷰 예정`

---

## 0. 북극성 (설계 기준)

> **"다키스트 던전의 반대 — 매뉴얼을 읽는 게임이 아니라, 몇 번 부딪히면 몸으로 아는 게임.
> 포켓몬 전투만큼 직관적인 육성형 로그라이크."**

모든 설계 결정은 이 한 문장으로 검증한다: **"이게 더 직관적인가? 읽지 않고 보면 아는가?"**

다키스트 던전이 무거웠던 근본 원인은 **숨은 수치와 숨은 계산**이었다. 우리는 이를 두 축으로 제거한다:
1. **계산을 없앤다** — 데미지는 상수, 능력치 연산 최소화.
2. **변형을 까발린다** — 모든 보정은 `원본 → 현재`로 화면에 병기.

### 0.1 대원칙: 엔진은 일반형, 모드는 제한된 설정

> **엔진은 가장 일반적인(maximal) 경우를 구현한다. 각 게임 모드는 그 일반 엔진을 "설정으로 제한"한 것이다.**

- 깊이(다키스트식 위치/포메이션)는 **엔진의 일반성**에서 나온다.
- 직관성(포켓몬식 단순함)은 **기본 모드의 제한된 설정**에서 나온다.
- 그래서 "직관 vs 깊이"는 충돌하지 않는다. 둘 다 가진다.

예시: 전체 위치 시스템을 구현해두고 "1행만" 설정 → 단순 모드 / 턴서열을 모듈로 분리해
라운드제·스타레일식을 갈아끼움 / 적 슬롯 4→5는 파라미터.

### 0.2 수치 투명성 원칙

- 모든 능력치·데미지는 **절대불변 고정값이 아니다.** 성장/버프/디버프/특수효과가 언제든 보정한다.
- 보정이 걸리면 화면엔 **`원본 → 현재`** 로 병기한다. (예: 데미지 `30 → 45`, 회피 `20 → 35`)
- 플레이어가 **상태창을 펼쳐 직접 계산할 일이 없어야** 한다. 필요한 결과 수치는 그 순간 그 자리에 뜬다.

## 1. 장르 정의

| 항목 | 결정 | 상태 |
|---|---|---|
| 대장르 | **육성형 로그라이크** | ✓ |
| 덱빌딩 | **제외** (읽을거리가 너무 많아 북극성 위반) | ✓ |
| 멘탈 모델 | **포켓몬 배틀**(1턴 1행동, 유닛당 스킬 4개) **+ 진형식 위치 전투** | ✓ |

**육성형 로그라이크란?** 캐릭터(사람)를 **영구히 키워서** 보유하고, 매 출격마다 그중 일부를
파티로 편성해 연속 전투를 돌파한다. 캐릭터의 성장은 판과 판 사이에 **남는다**(메타 진행 = 로그라이트의 "기억 회랑/계승").

핵심 재미 루프:
```
캐릭 키운다 → 파티 짠다 → 출격해 시험한다 → 배운 걸로 더 잘 키운다 → 다시 출격
```

## 2. 전투 — 코어

### 2.1 전장(Battlefield)

| 항목 | 결정 | 상태 |
|---|---|---|
| 형태 | 진형식 턴제 | ✓ |
| 좌표계 | **2D 그리드 `(행, 열)`** | ✓ |
| **아군 그리드** | **4열 × 4행 (16칸) 확정.** 파티 ≤4명을 이 안에 배치 | ✓ |
| **적 그리드** | **기본 4×4, parameterizable.** 적 수는 4일 필요 없음 (예: 6×6에 36마리도 가능) | ✓ |
| 단순/기본 표시 | 기본 예시는 4 vs 4, 단 양측 그리드·적 수는 가변 | ✓ |
| 일반화 | 대원칙 0.1: 엔진은 임의 그리드, 모드가 제한 | ✓ |

- **아군 전장은 4×4 그리드로 확정**(파티 ≤4명 배치). 한 줄로 세우는 것도 가능하지만 격자 자체는 4×4 — 포메이션(6장)이 여기서 작동.
- 멘탈 모델은 **포켓몬 트리플 배틀**(늘어선 유닛 + 위치/인접성이 의미를 가짐)에서 출발, 4×4 + 열보너스로 확장.

### 2.2 턴 순서 (라운드제 — 기본 모드)

| 항목 | 결정 | 상태 |
|---|---|---|
| 기본 모드 | **라운드제**: 한 라운드 = 모든 유닛이 정확히 1번씩 행동 | ✓ |
| 서열 결정 | 라운드 초기화 때마다 각 유닛이 **자기 SPD 범위에서 주사위**를 굴려 이번 라운드 SPD 확정 | ✓ |
| 정렬 | 행동 서열 = `행동수치 / SPD` → **SPD 높을수록 먼저** 행동 | ✓ |
| 모듈화 | 턴서열은 교체 가능한 모듈(`TurnOrderResolver`). **스타레일식 연속 타임라인(빠르면 더 자주)**은 별도 모드로 후속 구현 | ✓ |

- `행동수치`(분자)는 공통 상수로 가정(예: 10000). → `상수 / SPD`가 작을수록 먼저. ☐ 정확한 상수값 후속.
- 노트의 `R / R2`는 **라운드 1, 라운드 2** 의 행동서열 표였음(속성/랭크 아님).

### 2.3 행동 경제 & 스킬 슬롯

| 항목 | 결정 | 상태 |
|---|---|---|
| 한 턴 행동 | **여러 선택지 중 1개만 실행 = 턴 종료** (포켓몬식) | ✓ |
| 보유 스킬 | 유닛당 최대 **`x`개 보유**(4.2) | ✓ |
| 전투 활성 슬롯 | **전투 전 4개 선택**, 전투 중 고정 | ✓ |

> 의사결정이 "**무슨 스킬을, 누구에게**" 둘로 압축된다. (보유 풀에서 4개를 고르는 건 전투 전 단계 — 4.2/4.5 참조)

### 2.4 타겟팅 — 위치 마스크

| 항목 | 결정 | 상태 |
|---|---|---|
| 표현 | 스킬마다 **2개의 위치 마스크**: `사용가능 칸 집합` + `타겟 칸 집합` (2D 그리드 좌표) | ✓ |
| 일반성 | 포켓몬식 인접 규칙·근접/원거리는 모두 마스크로 표현 가능(마스크가 상위집합) | ✓ |
| 표시 | 화면에 **칸 색으로 표시**(예: 사용가능=파랑, 타격=빨강). 글 안 읽고 칸 색만 봐도 이해 | ✓ |

### 2.5 데미지 모델

| 항목 | 결정 | 상태 |
|---|---|---|
| 데미지 | **스킬에 박힌 상수(flat).** 공격력/방어력 능력치 **없음** | ✓ |
| 보정 | 버프/디버프/상태이상/특수효과가 반감·증폭 가능 | ✓ |
| 표시 | 보정 시 **`원본 → 현재` 병기** (예: `30 → 45`, `30 → 15`) | ✓ |
| 속성/타입 | **현재 없음** (필요해지면 대원칙대로 후속 확장) | ✓ |

### 2.6 능력치 (Stats)

> 전부 **보정 가능한 기본값**이다. 절대불변 고정값 아님. 보정 시 `원본 → 현재` 병기.

| 능력치 | 역할 | 기본/비고 | 상태 |
|---|---|---|---|
| **HP** | 체력. 0이면 전투불능 | 유닛 고유 | ✓ |
| **SPD** | 라운드 행동서열 결정 | 유닛 고유 **범위**(예: 4~7), 매 라운드 주사위 | ✓ |
| **DEX (민첩)** | **회피**. 높을수록 안 맞음 | 유닛 고유 | ✓ |
| **명중률** | 명중 판정에 가산 | 유닛 **기본 0** + 스킬에 내장된 명중률 | ✓ |
| **crit%** | 치명타 확률 | 기본 **10%** (보정 가능) | ✓ |
| **crit 배수** | 치명타 시 데미지 배수 | 기본 **×1.5** (보정 가능) | ✓ |

- **공격력/방어력 능력치는 없다.** 데미지는 스킬 상수.

### 2.7 명중 판정

| 항목 | 결정 | 상태 |
|---|---|---|
| 공식 | `실제 명중% = (공격자 명중률[기본0+보정] + 스킬 명중률) − 타겟 DEX` (0~100% 클램프) | ✓ |
| 필중 | 일부 스킬은 공식을 무시하는 **"필중" 플래그** 보유 가능 | ✓(개념 채택) |
| UI | 대상 지정 시 **실제 명중%를 적 머리 위에 표시** → 플레이어는 회피율 계산 불필요 | ✓ |

### 2.8 치명타

| 항목 | 결정 | 상태 |
|---|---|---|
| 판정 | 공격자 `crit%`로 굴림 → 성공 시 데미지 `× crit배수` | ✓ |
| 표시 | 데미지 병기 규칙 동일 (예: `30 → 45`) | ✓ |

### 2.9 방어 = 쉴드(Shield)

| 항목 | 결정 | 상태 |
|---|---|---|
| 개념 | **받피감%가 아니라 쉴드.** 상한이 있는 **임시 추가 체력(덤 HP)** | ✓ |
| 동작 | 피해는 **쉴드부터** 깎고, 쉴드가 0이 되면 HP를 깎음 | ✓ |
| 부여 | 능력치가 아님. 버프/효과로 부여 | ✓ |
| 표시 | HP 바 위에 **다른 색 칸**으로 표시(보이는 방어) | ✓ |
| 상세 | 상한값/지속/중첩 규칙 | ☐ 후속(상태이상 챕터에서) |

### 2.10 스킬 쿨타임(cooldown)

| 항목 | 결정 | 상태 |
|---|---|---|
| 분담 원칙 | **메커니즘=엔진, 값=스킬 데이터** (데미지·상태이상과 동일 패턴, 8.6) | ✓ |
| 쿨타임 값 | 스킬마다 선언 (예: "쿨타임 3") | ✓ |
| 엔진 책임 | 유닛별·스킬별 **잔여 쿨타임 추적 + 감소 + 사용 차단** | ✓ |
| **모니터링** | 쿨타임 잔여 = **관측(observation) 1급 필드.** `getLegalActions()`는 쿨다운 중 스킬을 자동 제외 | ✓ |
| **단위·감소** | **그 유닛의 턴 단위.** 쿨타임 3 = 사용 후 그 유닛의 다음 3턴 잠금, 4번째 턴에 재사용. 유닛의 턴이 올 때마다 1 감소 | ✓ |
| **전부 쿨다운 폴백** | **기본 공격 없음.** 효과 없는 **스킵(패스)**으로 턴을 넘긴다. 단 **"지금 쓸 수 있는 기술 없음"을 명확히 알림** (허비된 턴 = 쿨타임 관리 실패 페널티) | ✓ |
| **리셋 범위** | **웨이브 사이엔 유지**(한 노드=연속 전투), **노드(전투)가 바뀌면 리셋** | ✓ |

### 2.11 끼어들기(interrupt) — 서열에 비집고 드는 번외 행동

> 스타레일 "추가 턴"의 문제: "턴"이라 부르면 "쿨다운/지속시간이 도는 정규 턴"으로 오해되어 매번 각주가 필요.
> 우리는 **이름·연출·관측이 "정규 턴 아님"을 구조적으로** 말하게 해서 각주를 없앤다.

| 항목 | 결정 | 상태 |
|---|---|---|
| 명칭(도메인) | **「끼어들기」** (영문 `interrupt`). "행동 서열에 비집고 끼어든 1회 행동" — 추후 변경 가능(난입/새치기 등 후보) | ✓ |
| 발동 | 캐릭터 특성/스킬이 발동시킴. 행동 서열에 **동적 삽입**되는 1회 행동 | ✓ |
| **출처 일반화** | 끼어들기는 **스킬에 국한되지 않음.** 출처 = ① 스킬(`grantsInterrupt`) ② 버프/상태(`grantsInterrupt`, 예: 신속) ③ 향후 캐릭 특성. 실행·미리보기가 **단일 함수 `predictInterruptSubjects`** 공유 | ✓ |
| **주체(subject)** | 끼어들기 주체가 **행동자 본인이 아닐 수 있음.** `grantsInterruptTo: self\|target` — 서포트(재촉)는 **대상 아군**이 끼어들기 | ✓ |
| 발동 조건 | **정규 턴 행동 시에만** 발생(끼어들기 턴은 연쇄 방지로 제외) | ✓ |
| 예고(웹) | 타겟팅 중, 삽입 위치에 **유령 칸이 밖→안 슬라이드+깜빡 + 끼어들기 "주체 이름" 표시**(서포트면 다른 캐릭). "예고" 텍스트 없이 초록 모션만으로 전달 | ✓ |
| **핵심 규칙** | 끼어들기는 **쿨타임·지속시간을 차감하지 않는다.** 모든 차감은 **정규 턴 기준** | ✓ |
| 주기 효과 | **화상(턴 종료)·중독(턴 시작)은 정규 턴만 기준** (끼어들기 횟수와 무관) | ✓ |
| **출혈 예외** | **출혈은 정규 턴 + 끼어들기 턴 — 모든 "행동 시" 발동**(끼어들기 남발의 카운터). 단 **출혈 지속시간 차감은 정규 턴만** | ✓ |
| 연출 | 서열 바에서 **정규 턴 사이가 벌어지며**, 더 넓고 튀어나온 **초록 하이라이트 토큰**이 삽입됨 | ✓ |
| 관측 | `actionOrder` 항목에 `kind: "normal" \| "interrupt"` 플래그 → 사람 연출과 동일 정보를 기계에도(8.2) | ✓ |

## 3. 상태이상 & 특수효과

### 3.1 통일 모델 — "타임드 인스턴스 원장(ledger)"

| 항목 | 결정 | 상태 |
|---|---|---|
| 기본 방식 | **스택형(B)**: 세기는 스택, 시간은 별도 지속턴 (둘을 분리) | ✓ |
| 저장 구조 | 상태이상 = **타임드 인스턴스의 목록**. 적용 1건 = `{출처, +스택, 잔여턴}` 1개 인스턴스 | ✓ |
| 합산 | **현재 총 스택 = 인스턴스들의 합.** 인스턴스는 합치지 않고 각자 독립 만료 | ✓ |
| 효과는 사실 | "3→1로 줄어듦"이 계산이 아니라 **데이터에 박힌 사실**로 표현됨 (출처/만료 자동 보존) | ✓ |

```
예) 화상 = [
  { 출처: 아군A 화염스킬,  +2스택, 잔여 3턴 },
  { 출처: 함정,           +1스택, 잔여 1턴 },
]   → 현재 총 스택 3, 다음 턴 함정분 만료되어 1로 감소
```

### 3.2 표시 — 점진적 공개(progressive disclosure)

**글랜스(아이콘, 한눈):**
| 위치 | 표시 | 뜻 |
|---|---|---|
| 아이콘 | 🔥 | 상태 종류 (색·모양으로 즉시 구분) |
| superscript | ³ | **현재 총 스택**(세기) |
| subscript | ₅ | **완전 소멸까지 남은 턴**(가장 늦은 인스턴스) |
| `▾` 마커 | 🔥³˙⁵▾ | **다음 변화까지 턴**(가장 빠른 만료) — "곧 약해진다" |
| 아이콘 ↑/↓ | — | 이번 턴 스택 **추세**(증가/감소) — 호버 없이 모멘텀 인지 |

**호버(상세 창):** 원장을 그대로 표시 — **각 인스턴스의 출처·스택·잔여턴**. (누가 건 효과인지 보임)

### 3.3 북극성 사수 라인 ⚠️

> **기본 플레이는 글랜스(³/₅/▾/추세)만으로 충분해야 한다.**
> **호버는 최적화·민맥싱용 보너스 정보다. 호버를 안 보면 못 깨는 게임이 되면 북극성 위반.**

이 모델은 깊이를 위해 직관성을 *의도적으로 조금* 양보한 결정이며, 위 라인이 그 양보의 한계선이다.

### 3.4 두 갈래: 전역 상태이상 vs 특수효과

- **전역(global) 상태이상**: 규칙·세기가 **표준화**되어 어디서나 동일. 세기가 고정이라 글랜스 표기가 거짓 없음.
- **특수효과(source-dependent)**: 세기/거동이 **출처에 따라 다름**. 그래서 버프/상태 목록에 표시하되 **펼치면 출처**가 보여야 함(3.1 원장 모델이 이걸 자동 처리).

### 3.5 전역 상태이상 목록 (표준화)

| 효과 | 거동 | 세기 | 발동 시점 |
|---|---|---|---|
| **화상** | 지속 피해 | 스택당 `x` | **턴 종료 시** |
| **중독** | 지속 피해 | 스택당 `x` | **턴 시작 시** |
| **출혈** | 지속 피해 | 스택당 `x` | **행동 시** (정규 턴 + 끼어들기 모두 — 2.11) |
| **마비** | SPD 하락 → **행동 서열 재배열로 밀림** | (밸런스) | 상시 |
| **동상** | **주는 데미지 50% 하락** | 고정 ×0.5 | 상시 (공격 시 적용) |
| **빙결** | 행동 서열에서 **비활성화 = 그 턴 행동불가** | — | 해당 턴 |
| **공포** | **쉴드 깎는 효율 악화**: 들어온 피해 1이 쉴드를 **(공포 스택)만큼** 깎음. (예: 6스택 → 피해1이 쉴드 6 깎음). **단 HP 깎는 효율은 불변** | 스택 배율 | 피격 시(쉴드에만) |

> `x`(화상·중독·출혈의 스택당 피해)는 임시 placeholder. 밸런스 조정으로 확정. ☐
> 공포: 스택 배율이므로 1스택=등배(실효 미미), 2스택+부터 의미. 밸런스 시 조정 가능. ☐

### 3.6 특수효과 목록 (출처 의존)

| 효과 | 거동 | 비고 |
|---|---|---|
| **관통** | (아군 부여) 적이 쉴드를 가져도 공격이 **쉴드 무시하고 온전히 HP를 깎음** | 쉴드 레이어 우회 |
| **재생** | 턴 종료 시 회복 | 회복량이 출처마다 달라 전역 아님 → 버프목록+출처 |
| **불사** | HP가 0이 되어도 **1턴 동안 죽지 않음** | 버티기 |
| **공위증** | **주는 데미지 합연산 +** (버프) | 정도가 출처마다 달라 전역 아님. 버프목록에 `공위증(데미지 합연산)` 표시, 펼치면 출처 |

### 3.7 데미지 보정 규칙 (전역 원칙)

| 규칙 | 결정 | 상태 |
|---|---|---|
| 가변 데미지 버프(공위증류)는 **합연산(flat)만**. **% / 곱연산 없음** | ✓ | ✓ |
| 곱연산은 **표준화된 전역 상태이상만** 사용 가능 (예: 동상 ×0.5). 가변/출처의존 효과는 합연산만 | ✓ | ✓ |
| **데미지 계산 순서**: `(스킬상수 + 합연산보정) × 전역배율(동상 등) × crit배수` → 결과는 `원본→현재` 병기 | ✓ | ✓ |

> 예: 스킬 20, 공위증 +10, 동상, 크리 → `(20+10) × 0.5 × 1.5 = 22`. 화면 표기 `20 → 22`.

### 3.8 ★ 도출된 일관성 — "방어는 오직 쉴드 레이어"

전역/특수 효과를 종합하면 다음 구조가 도출됨 (✓ 확정):
- **HP에 들어가는 피해 자체는 방어측이 감소/증폭하지 못함.** (받피감% 없음 — 이미 확정)
- **공격측**만 자기 출력을 보정: 동상(−), 공위증(+).
- **방어측**은 오직 **쉴드 레이어**만 조작: 쉴드량 / 공포(쉴드 잠식 가속) / 관통(쉴드 무시).
- → "버티는 건 보이는 쉴드로만, 무너뜨리는 건 공포·관통·DoT로." 매우 선명한 구조.

### 3.9 프리미티브(엔진용 역도출)

위 효과들을 엔진이 아는 원자 단위로 환원:
1. **시점부 지속피해** `{trigger: 턴시작|턴종료|행동시, amount: 스택×x}`
2. **시점부 지속회복** `{trigger: 턴종료, amount: 출처정의}`
3. **능력치 보정** (SPD↓ 등 → 서열 재계산 트리거 포함)
4. **주는 데미지 보정** (합연산 / 전역고정배율)
5. **행동 봉쇄** (서열에서 비활성)
6. **쉴드 부여** (상한 있는 덤 HP)
7. **쉴드 잠식 배율** (공포)
8. **쉴드 무시** (관통)
9. **사망 방지** (불사, 1턴)
10. **주는 데미지 합연산 보정** (투지/공위증+ · 약화−), **치명 보정**(예리·은신: critChanceAdd/critMultiplierAdd)
11. **무적**(모든 피해 0) · **도발**(적 공격 집중, AI 참조) · **마비**(speedDown→서열 밀림, 3.5)
12. **정화**(cleanse) · **시전자 자기효과**(applyStatusSelf, 광역 중복 방지)
13. **면적(AoE) 모양**: `area` = single/row/col/square(radius)/cross(radius)/all/**free(자유 인접 N칸)**. **앵커=선택 칸(빈 칸도 가능)** 기준으로 영향 칸 결정, 풋프린트 내 같은 진영 유닛에 적용. **타겟팅은 셀 기반**(유닛 없는 칸도 클릭), 웹은 **바닥에 영향 칸 하이라이트 + 자유선택 단계별 인접 칸 제시**(2.4 확장).

## 4. 캐릭터 & 성장 시스템 (육성)

### 4.1 캐릭터 모델 — "포켓몬式 고유 디자인"

| 항목 | 결정 | 상태 |
|---|---|---|
| 클래스 | **없음.** 캐릭마다 **고유 디자인**(포켓몬 종처럼 1:1 설계) | ✓ |
| 자유도 | 아무 스킬이나 배우는 자유형 **아님** | ✓ |
| 학습 범위 | **캐릭터 디자이너가 "뭐는 되고 뭐는 안 되는지"를 캐릭마다 명시적으로 설계** (= 포켓몬 무브풀) | ✓ |

→ 각 캐릭 = `{고유 기본능력치, 학습가능 스킬 목록(learnset), 정체성/외형}`. 클래스 추상화 없음.

### 4.2 파워 레버 — 두 축으로 분리

> **핵심: 스탯과 데미지의 성장 경로가 분리된다.** 스탯은 장착으로만, 데미지(기본 위력)는 스킬 강화로만.

| # | 레버 | 정체 | 성장 경로 |
|---|---|---|---|
| 1 | **기본 능력치** | HP/SPD/DEX/명중률/crit%/crit배수 | **오직 장착 아이템(장착/업그레이드)으로만.** 레벨로 안 오름 |
| 2 | **스킬** | 보유 풀에서 전투 전 **4개 선택** | **새 스킬 획득 + 스킬 강화.** 기본 데미지가 오르는 **유일한** 길 |
| 3 | **장착 아이템 (3칸)** | 무기 · 방어구 · 지닌 물건 | 영구 수집 + 판중 임시 |
| 4 | **포메이션 위치** | 그리드 배치(6장) | 상황적 |

- **판 중(출격)**: 캐릭 레벨업/스탯상승 **없음**. 보상 = 새 스킬(전용기 포함) 또는 **스킬 강화권**.
- **스킬 보유 수**: 최대 `x`개 보유, **전투 전 4개 선택**. (`x` = ☐ placeholder)
- 룬 시스템은 폐기. 변형은 장착 아이템 3칸 + 스킬 강화로 표현.

### 4.3 장착 아이템 — 3칸 (도메인 명칭 확정)

| 칸 | 역할 | 예시 | 상태 |
|---|---|---|---|
| **무기** | 공격 측 보정 | 공격 상수 **+N**(합연산), 크리% 보정 등 | ✓ |
| **방어구** | 생존 측 보정 | HP +N, **쉴드 획득량 +N** 등 (받피감 아님 — 3.8 준수) | ✓ |
| **지닌 물건** | (포켓몬 지닌물건류) | — | ☐ 후속 (나중에 정의) |

> 명칭 `무기 / 방어구 / 지닌물건`이 **확정 도메인 용어**다.

### 4.4 숙련도(영구 본체 레벨) — "기술 폭"을 해금

| 항목 | 결정 | 상태 |
|---|---|---|
| 본체 레벨(숙련도) 역할 | **스탯을 올리지 않는다.** 그 캐릭이 **습득 가능한 기술의 폭(tier)을 넓힌다** | ✓ |
| 메커니즘 | 스킬마다 **해금레벨(tier)** 이 할당됨. 본체 경험치가 해당 해금레벨에 도달해야 그 tier 스킬이 **보상 선택지에 출현 가능** | ✓ |
| 경험치/레벨 | 영구(본체). 판 중 캐릭 레벨업 없음. 5.3대로 천천히 상승 | ✓ |
| 효과 | 낮은 숙련도 = 기본 기술만 등장 / 높을수록 더 강하고 다양한 기술이 보상 풀에 진입 | ✓ |

### 4.5 전투 보상 화면 (판 중 성장의 전부)

전투 클리어 시 보상 선택 화면이 뜬다.

| 항목 | 규칙 | 상태 |
|---|---|---|
| **기술 보상** | **항상 등장. 선택지 3개 중 1개 선택(택1).** | ✓ |
| 기술 선택지의 정체 | (a) **새 스킬 획득**(보유 풀 `x`에 추가) 또는 (b) **이미 보유한 스킬 강화(중첩=티어 업)** | ✓ |
| 출현 범위 | 본체 숙련도(4.4)가 해금한 tier 내에서 추첨 | ✓ |
| **장신구(=장착 아이템)** | 보상으로 **나올 수도, 안 나올 수도** 있음 | ✓ |

### 4.6 스킬 강화 구조 — "설계된 티어"

| 항목 | 결정 | 상태 |
|---|---|---|
| 방식 | **작가가 스킬마다 설계한 티어 경로.** Lv1→2→3… 단계마다 데미지 상수↑ 또는 효과 추가 | ✓ |

## 5. 로그라이크 루프 — 본산 & 기억 회랑

### 5.1 루프 구조: "기억 회랑" 하이브리드 (C안)

| 항목 | 결정 | 상태 |
|---|---|---|
| 캐릭터 본체 | **본산에서 영구 보유·육성.** 절대 소실되지 않음 | ✓ |
| 출격 | 본체의 **사본/현신**이 출격 (본체는 본산에 안전) | ✓ |
| 한 판 중 성장 | 그 판 한정 = **로그라이크 "런 빌드"** (판이 끝나면 휘발) | ✓ |
| 죽음/전멸 | 그 판의 진행·런빌드를 잃음. **본체는 무사** | ✓ |
| 계승 | 판 결과의 **일부만** 기억 회랑을 통해 본산에 영구 반영 | ✓ |

**설계 의도 — 두 유저층을 동시에:**
- *순간 판단형*: 판 중 성장이 휘발 → 매 출격이 자기완결 전술 샌드박스. ✓
- *애정 육성형*: 본체 영구 + 계승 → 투자·정체성 기반 애착. (위험 애착이 아니라 **투자·정체성 애착** — 포켓몬 모델) ✓

### 5.2 ★ 핵심 원칙: 두 보상 트랙 분리 (하데스 모델)

> **한 판은 그 자체로 재미·완결되어야 한다(이기든 지든 그 판의 전술이 보상).**
> **영구 계승은 그 위에 얹는 별도 레이어다. 둘은 같은 자원을 공유하지 않는다.**

- 실패 모드 방지: 계승이 너무 짜면 허무/노가다, 너무 후하면 한 판 긴장 증발.
- 두 트랙을 분리하면 **한쪽을 위해 다른 쪽을 깎지 않아도** 둘 다 만족.
- 메타는 더해주되 **게이트하지 않는다**(순간형을 막지 않음).

### 5.3 계승의 정체 (무엇이 영구로 넘어가나)

| 종류 | 영구 반영 정도 | 상태 |
|---|---|---|
| **(나) 해금** (새 캐릭·스킬·기술머신 등 "할 수 있는 것" 확장) | **주력** — 캐릭 스탯은 안 건드려 순간형 긴장 보존 | ✓ |
| **(다) 자원/재화** (본산 육성에 쓰는 통화) | **주력** | ✓ |
| **(가) 경험치/레벨 계승** | **소량** — 캐릭이 천천히 영구 성장 | ✓ |

> "본산"은 캐릭이 살고 눈에 보이게 성장하는 집(정체성 애착의 무대), "기억 회랑"은 판→영구로
> 일부를 흘려보내는 계승 장치, "기술머신"은 해금/스킬 부여 수단(4장 성장과 연결).

## 6. ★ 포메이션 변주 시스템 (차별점)

> 방식: **창발적 위치 효과(A2)** — 명명 진형 프리셋(A1) 아님. "어디 서 있는지 자체"가 효과를 만든다.

### 6.1 핵심 메커니즘 — 열(column)별 보너스 + 총량 보존

| 항목 | 결정 | 상태 |
|---|---|---|
| 단위 | **각 열(column)이 고정된 "보너스 총량"을 제공** | ✓ |
| 분배 | 그 총량은 **해당 열에 선 유닛 수로 나눠 분배(총량 보존)** | ✓ |
| 효과 | 몰빵(1명=전부) vs 분산(N명=각 1/N)의 트레이드오프가 **위치만으로** 발생 | ✓ |
| 표시 | 각 유닛이 받는 실제 보정은 그 자리에 병기(수치 투명성 0.2) | ✓ |

**예시** (열 보너스 배치):
```
1열: 공격 스킬 위력 +4      3열: 방어 스킬 위력 +4
2열: 공격 스킬 위력 +4      4열: 방어 스킬 위력 +4
```
- 4열에 3명 → 각자 방어스킬위력 +4/3
- 4열에 1명 → 그 1명에게 +4 몰림

### 6.2 그리드

- **아군 4×4 확정** (2.1). 한 열에 최대 4명까지 겹쳐 설 수 있음 → 총량보존 트레이드오프 성립.
- **적 기본 4×4, parameterizable** (2.1).

### 6.3 변주의 원천 — 표준 vs 보스 기믹

| 항목 | 결정 | 상태 |
|---|---|---|
| 일반 전투 | 열 보너스 배치가 **통일된 표준**으로 적용 | ✓ |
| 보스/특수 | **보스 기믹으로 진형 효과 변경** (디자이너 자유 설계) — "변주"가 여기 집중 | ✓ |
| 적 진형 보너스 | **기본 미적용**(일반 적은 배치만). **보스전에만** 적 진형 보너스 적용 | ✓ |

### 6.4 동적 재배치 (핵심 전술)

| 항목 | 결정 | 상태 |
|---|---|---|
| 격상 | 밀치기/끌기/자리바꿈으로 적·아군을 다른 열로 옮기는 것을 **핵심 전술로 격상** | ✓ |
| **이동 규칙** | **이동기(스킬)를 가진 유닛만 이동 가능. 이동기가 없으면 그 캐릭은 못 움직인다** | ✓ |
| 도입 | 점진적 — 처음엔 일부 스킬만 이동 효과 겸비 | ✓ |
| 시너지 | 위치 마스크(2.4) + 열보너스(6.1) + 보스 진형 기믹(6.3) | ✓ |

## 7. 런(run) 구조 & 승패

> 멘탈 모델: **붕괴 스타레일 "차분화 우주"** (다층 로그라이크 진행).

### 7.1 맵 위상 — 헥스 인접 무방향그래프 (클리어 노드 목표)

| 항목 | 결정 | 상태 |
|---|---|---|
| 기본 위상 | **헥스 인접 무방향그래프**. 노드(`MapNode`, axial `(q,r)`=헥스 격자 위치) + **무방향 변**(`MapEdge`) — 변은 **맞닿은(인접) 헥스끼리만**. 디자이너가 인접 변을 켜고 끔(전부 켜면=순수 인접이동). | ✓ |
| 이동/진행 | **재방문 불가(전진만)**: 맞닿은 **미방문** 이웃으로만 이동, 방문 칸 잠금. 우회=더 긴 경로. 막힌 이웃(미방문 경로로 clear 못 감)은 자동 비활성(`liveReachable`). | ✓ |
| 목표/종료 | **클리어 노드**(전투 없는 목표 마커). 진입 = 층 종료. **보스는 길목**(일반 전투 노드). 다중 보스/클리어 = 갈림길 → **아무 클리어 노드나 진입하면 층 완료**. | ✓ |
| 도달성 불변식 | 변은 **맞닿은 헥스끼리만**(`hexAdjacent` 검증). 모든 노드는 entry 연결성분에 ∧ 그 성분에 clear 존재. 저장 시 `validateRun`(비인접 변·고립 노드 거부). | ✓ |
| 저작/생성 | **절차생성(genMap) 폐기.** 손으로 짠 **레포 JSON**(`data/runs/*.json`)만 — 에디터 GUI가 저작·내보내기. 엔진은 `RunDef` 해석만. | ✓(엔진) / 에디터 ☐ |
| 렌더 | axial→픽셀(`x=W(q+r/2), y=1.5·size·r`) 절대배치 + **무방향 변 선**(화살표 없음; 현재 위치의 활성 경로 강조, `runRender.ts mapScreen`). | ✓ |
| 중첩(nested) | 노드 선택 후, 원하면 **한 단계 미시적 진행**을 셀 내부에 끼울 수 있음. 매크로=그래프, 마이크로=셀 내부 | ☐ |

### 7.2 노드 종류 (6종, 시작 세트)

| 노드 | 설명 |
|---|---|
| **일반전투** | 기본 전투 |
| **엘리트전투** | 강적, 더 좋은 보상 |
| **상점** | 범용 강화권(4.6)·아이템 구매 |
| **인카운터** | **생존은 어느 정도 보장**되나, **성장 또는 성장저해를 도박**하는 노드 (리스크/리워드) |
| **휴식 노드** | 회복 또는 강화 |
| **보스 노드** | 강적·최대 보상. **층의 끝이 아니라 길목** — 층 종료는 클리어 노드 진입으로 |
| **클리어 노드** | **목표 마커(전투 없음)**. 진입 시 층 종료. 디자이너가 보스 뒤에 배치 → 자연히 보스를 거쳐 도달 |

> **런 골드 (확정, 구현됨)**: 런 내부 통화. 전투 승리(일반 8/엘리트 16)·인카운터로 획득, **상점에서만 소비**(강화권·범용기·회복). **본산 메타 재화(5.2 (다))와 별개**(5.2 "둘은 같은 자원을 공유하지 않는다" 준수). 가격/획득량은 ☐ 밸런스.

### 7.3 런 길이/단위

| 항목 | 결정 | 상태 |
|---|---|---|
| 구조 | **다층(multi-layer)**. 층마다 클리어(목표) 노드 ≥1. 층 = **선형 체인**(클리어→다음 층 entry; 분기 층 그래프는 후속) | ✓ |
| 기본값 | 한 런 = **3층** | ✓ |
| 층별 노드 수 | 개발하며 결정 | ☐ |
| **층 수 = parameterizable** | 챌린지 모드(몇 층까지 오르나) + **점수 제도** 가능 | ✓ |
| 승/패 | 전멸 = 런 실패 / 최종 보스 = 클리어 (기본) | ✓ |
| 웨이브 | 노트의 "연속 전투·웨이브" = **전투 노드 내부의 연속 파도**(적 1~N 파) | ✓ |

### 7.4 모드와의 관계

> **모든 모드(캠페인 / 일반 / 챌린지 등)는 이 런 구조를 베이스로 한다.** 모드 = 이 베이스의 제한·확장 설정(대원칙 0.1).
> 노트 원안 모드: `1:多 캠페인`, `多:多 일반`. 각 모드의 구체 규칙은 후속. ☐

## 8. 자체 엔진 & 모니터링 인프라

> 목표: 게임 시스템을 **사람 육안으로 확인 가능** + **AI가 직접 플레이 가능** + **모니터링이 아주 잘 되는** 자체 엔진.

### 8.1 근본 아키텍처 — 헤드리스 코어 + 다중 뷰

| 계층 | 역할 | 상태 |
|---|---|---|
| **코어(Core)** | 렌더링 0 의존. `상태 + 행동 → 다음 상태`인 **순수 시뮬레이션**. 상태를 구조화 데이터로 통째 노출 | ✓ |
| **텍스트 뷰 / CLI** | 보드를 matrix/array 텍스트로 출력 + 터미널 명령으로 행동 주입 — **AI·모니터링의 1급 인터페이스** | ✓ |
| **웹 렌더러(사람용)** | 코어 상태를 예쁘게 그림. **AI 플레이에 불필요**(사람 관전·플레이용). 후순위 | ✓ |

> 셋이 같은 코어를 공유 → "사람이 보는 것 = AI가 읽는 것 = 진실" 자동 보장.

### 8.2 ★ AI 인터페이스 원칙 — "터미널로 플레이"

> **AI는 스크린샷이 아니라 구조화된 관측(observation)과 터미널 명령으로 게임을 완전히 플레이한다.**
> 이는 수치 투명성(0.2)의 기계 버전: **결정에 필요한 모든 정보가 observation에 있어야 한다(픽셀에 숨은 정보 0).**

| 요구 | 내용 | 상태 |
|---|---|---|
| **완전한 관측** | 보드 그리드(4×4 등)·유닛 스탯(원본+현재)·턴 서열 배열·상태이상 원장·쉴드 등 **모든 상태를 matrix/array/JSON로** | ✓ |
| **행동 공간 질의** | 현재 합법 행동(어떤 유닛이 어떤 스킬을 어느 칸에)을 **열거/질의 가능** → AI가 골라서 주입 | ✓ |
| **터미널 명령** | CLI로 상태 읽기 + 행동 실행 | ✓ |
| ASCII 렌더 | 보드를 텍스트 격자로 — 사람·AI 공통 가독 | ✓ |

### 8.3 ★ 결정론 + 시드 (1급 요구사항)

| 요구 | 내용 | 상태 |
|---|---|---|
| 결정론 | 전투는 주사위 천지(SPD·크리·명중·보상 추첨) → 코어는 **시드 기반 결정론**: *같은 시드 + 같은 행동 = 항상 같은 결과* | ✓ |
| 리플레이 | 시드 + 행동 로그로 **판 전체 재현**(버그 재현·"이 판 다시 보기") | ✓ |
| 이벤트 로그 | 모든 상태 전이를 이벤트로 기록(모니터링·디버깅) | ✓ |

### 8.4 기술 스택 — TypeScript 단일 (확정)

| 항목 | 결정 | 상태 |
|---|---|---|
| 스택 | **TypeScript 단일.** 코어(헤드리스, Node) + 웹 렌더러(사람) 동일 언어, **레이어로 분리** | ✓ |
| Tauri 비교 | 분리 철학은 같음(사람↔프론트 / AI↔코어). 단 언어는 하나라 IPC·직렬화 부담↓, 타입 공유 | ✓ |
| 내가 플레이 | 프론트 미경유. Node로 코어 직접: `getObservation()` / `getLegalActions()` / `step(action)` | ✓ |
| 결정론 | `Math.random` 금지 + 시드 PRNG + 정수/고정소수 연산 규율로 확보 | ✓ |

### 8.5 연출(그래픽/애니메이션)은 "이벤트 로그의 재생"

| 항목 | 결정 | 상태 |

| 원리 | 코어는 상태전이를 **이벤트 로그**(8.3)로 기록. **프론트가 그 이벤트 스트림을 연출로 재생** | ✓ |

### 8.6 데이터 주도 설계 (1급 원칙, 확정)

| 항목 | 결정 | 상태 |
|---|---|---|

### 8.7 구현 상태

**✅ 스캐폴딩 완료 (핵심 전투 수직 슬라이스)** — `src/`, 실행법 `README.md`.
- 코어(`src/core/`): **도메인별 모듈화 완료** — `types/`(content 스키마/runtime 상태)·`combat/`(턴서열·데미지·상태틱·타겟팅·면적·끼어들기·승패·관측 13모듈)·`run/`(맵·보상·노드·관측)·`ai/`·`util`. 진입 파일(`engine.ts`/`run.ts`/`observation.ts`/`types.ts`)은 얇은 배럴(파사드). 테스트 28개(결정론 포함) 통과, tsc 0에러. 파일 소프트캡 ~300줄(8.8/CLAUDE.md).

### 8.8 데이터 ↔ 엔진 경계 + 프리미티브 카탈로그 (1급 원칙, 확정)

8.6의 "메커니즘=엔진, 값=데이터"를 **누가 무엇을 만지는지**로 구체화한다. 이 경계가 모호하면 엔진에 콘텐츠가 슬금슬금 하드코딩되거나, 반대로 표현 불가능한 걸 데이터로 우겨넣게 된다.

| 영역 | 누가 | 무엇 | 어디 |
|---|---|---|---|
| **데이터** | 게임 디자이너 | 콘텐츠(스킬·상태이상·캐릭터·전투배치·노드 구성·열보너스). 기존 프리미티브의 **조합/수치** | `src/data/*` + `src/core/types/content.ts` 스키마 |

**프리미티브 카탈로그 (현재 엔진이 제공하는 원자)** — 디자이너는 이 목록의 조합으로만 콘텐츠를 만든다:
- **SkillEffect 종류**: `damage`·`status`·`shield`·`heal`·`move`·`interrupt`(+`applyStatusSelf`/정화). 효과 디스패치는 `combat/skills.ts`.
- **StatusDef 거동 필드**: DoT/HoT(틱 타이밍 turnStart/turnEnd/onAct)·SPD배율·주는뎀배율·받피해(쉴드잠식)·쉴드무시·1턴생존·crit±·공격±·도발·정화 등. 해석은 `combat/status.ts`+`util.ts`.
- **AreaShape 종류**: 단일·열·행·십자·면적(앵커 기준). 계산은 `combat/targeting.ts`(`computeAreaCells`).
- **Skill 필드**: `cooldown`·`accuracy`·사용가능칸/타겟칸 마스크·**`reach`(동적 도달 — 최전열부터 연속 n칸, 빈 열 건너뛰지 않음, 교착 방지, `targeting.ts reachableColumns`)**·`area`·`grantsInterrupt(To)`·`alwaysHit`.
- **TurnOrderResolver**: 라운드제(상수/SPD 주사위 서열). `combat/turnOrder.ts`.
- **특성/패시브 룰 엔진(when/if/then)**: 상시 효과의 디자이너 언어. `PassiveRule = {when:Trigger, if?:Condition[], then:Effect[]}`. **특성**=캐릭터(`data/traits.ts` `TraitDef`+`Character.traitIds`, 항상), **패시브**=스킬 **출전(활성 4)**(`Skill.passives`, `active` 태그로 능동/하이브리드 구분). 전투 훅이 `combat/passives/`의 `fireTrigger`를 인라인 호출(결정론 정렬·재진입 가드). **Trigger**(battleStart/round/turn/everyN/speedRoll/hit/miss/damage/heal/shield/status/move/kill/death/battleEnd…) · **Condition**(hpPct/round/everyN/hasStatus/위치/진영수/chance…) · **Effect**(damage/heal/shield/applyStatus/cleanse/removeStatus/move/grantInterrupt/statMod/modCooldown/modSpeedRoll/rerollSpeed/healByDamage(흡혈)/reflectByDamage(비율반사)/castSkill(액티브 자동시전; **leaf 스킬만**=passives 없는, `validateCastSkill`가 check 게이트서 강제·재귀 방지) · EffTarget other*=자신/대상 제외 광역). 적도 같은 엔진(skillIds passives + traitIds) — 적 특성 콘텐츠 가능. 카탈로그·작성법 = `src/data/README.md`. **모험(run) 스코프**: `run/passives.ts`가 `nodeEnter`/`nodeClear`/`actStart`/`goldGain`/`partyHpChange` 트리거 + `goldDelta`/`healParty`/`grantRunStatus`(계승) 효과 + `nodeTypeIs`/`goldAtLeast` 조건 해석. 전투/모험 같은 `PassiveRule` 스키마 공유.
- **런 노드 해소**: 전투생성·휴식/상점/인카운터·보상 3택1. `core/run/*`.
- **맵 그래프(헥스 인접 무방향그래프)**: `RunDef = { floors: FloorDef[] }`(층 선형체인), `FloorDef = { entryNodeId, nodes: MapNode[], edges: MapEdge[] }`, **무방향 변**(맞닿은 헥스끼리만). 엔진 `run/graph.ts`: `hexAdjacent`·`neighborIds`·`liveReachable`(재방문 불가·막힌노드 비활성)·`validateRun`(인접 변·도달성). 클리어 노드 진입=층 종료, 보스=길목. 저작=`data/runs/*.json`(레포 JSON, 에디터 출력). 스키마=`types/map.ts`. (구 `genMap`/`MapGenConfig`/`GameMode` 폐기)
- **AI 행동결정 정책(우선순위 룰)**: "턴이 왔을 때 합법 행동 중 무엇을 고를지"의 디자이너 언어(반응형 패시브와 별개의 *능동* 결정). `AiProfile = { rules: AiRule[] }`, `AiRule = {if?:AiCondition[], prefer?:SkillKindPref, target?:TargetPref, weight?}`. 위→아래 첫 적용가능(조건 참 AND 합법행동 존재) 룰이 결정, 없으면 **공유 그리디 fallback**(도발 우선·최저 HP·최고 명중). **prefer**(damage/heal/shield/applyStatus/cleanse/any) · **target**(lowest/highestHpEnemy·lowestHpAlly·front/backmostEnemy·self·anyEnemy/Ally) · **AiCondition**(selfHpPct·ally/enemyHpPctBelow·self/enemy HasStatus·selfMissingStatus·round·outnumbered·allyCount) · **weight**(backline/frontlineTarget·lowHpTarget·hitChance·critChance, 보조 정렬). 캐릭터가 `aiProfileId`로 참조(없으면 그리디=기존 동작). 결정론(rng 미사용, 동점=인덱스). 스키마=`core/types/ai.ts`, 해석=`ai/profile.ts`, 콘텐츠=`data/ai.ts`. 작성법=`src/data/README.md`.

**프리미티브-갭 결정 프로토콜 (필수·사용자에게 명시):**
새 기능 요청 → ① 기존 프리미티브 **조합으로 원자적으로 표현 가능한가?** → ② **가능 = 데이터-온리**(`src/data`만 수정, 엔진 불변) → ③ **불가 = 프리미티브 갭**: 엔진 변경 필요. 이때 **구현 전 사용자에게 정해진 형식으로 보고하고 승인받는다**:

> "이 기능은 새 엔진 프리미티브가 필요합니다 — **[무엇]**. 기존 [관련 프리미티브]로는 원자적으로 불가합니다(이유: …). 추가 위치: `types/content.ts`(스키마) + `core/<module>`(해석). 데이터-온리가 아닙니다."

**엔진 프리미티브를 말없이 늘리지 않는다.** 커밋/보고에 분류를 명시: `[데이터-온리]` 또는 `[엔진 프리미티브 추가]`. (예시 사례: 노드별 적 로스터를 `run.ts` 하드코딩 → `data/encounters.ts`의 `NODE_ROSTERS`로 이동 = "콘텐츠는 데이터로"의 시범.)

## 부록 A. 확정 결정 로그 (요약)

**철학·원칙**
1. 육성형 로그라이크 (덱빌딩 제외)
2. 북극성: 다키스트의 반대 / 포켓몬급 직관 / "읽지 말고 부딪혀 알기"
3. 대원칙: 엔진=일반형, 모드=제한된 설정 (전부 parameterizable)
4. 수치 투명성: 모든 값은 보정 가능한 기본값, `원본→현재` 병기

**전투 코어**
5. 전장: 아군 **4×4** 그리드, 적 기본 4×4(parameterizable, 6×6 등 가능)
6. 턴: 라운드제 기본(전원 1라운드 1행동), 라운드마다 SPD 주사위, 서열=상수/SPD. 스타레일 모드 후속
7. 타겟: 위치 마스크(사용가능칸+타겟칸), 칸 색 표시
8. 행동: 1턴 1행동. 스킬 **보유 x개 / 전투 활성 4개**
9. 데미지: 스킬 상수, ATK/DEF 없음, 속성 없음. 보정은 합연산만(곱연산=전역상태이상만). 순서 `(상수+합연산)×전역배율×crit`
10. 능력치: HP/SPD/DEX(회피)/명중률/crit%/crit배수 — 전부 보정 가능
11. 명중: (명중률+스킬명중)−DEX, 필중 플래그, 머리 위 명중% 표시
12. 방어: 오직 쉴드 레이어(상한 있는 덤 HP). HP피해 자체는 방어측이 못 줄임

**상태이상**
13. 통일 모델: 타임드 인스턴스 원장(스택+지속턴 분리, 출처 보존). 글랜스=스택/소멸턴/▾/추세, 호버=원장. 글랜스만으로 기본 플레이 충분
14. 전역: 화상(턴종료뎀)·중독(턴시작뎀)·출혈(행동시뎀)·마비(SPD↓)·동상(주는뎀×0.5)·빙결(행동불가)·공포(쉴드잠식 가속)
15. 특수: 관통(쉴드무시)·재생·불사(1턴 생존)·공위증(주는뎀 합연산+)

**캐릭터·육성**
16. 캐릭터: 클래스 없음, 포켓몬式 고유 디자인 + 작가 설계 learnset
17. 스탯=오직 장착(무기/방어구/지닌물건)으로만. 데미지=오직 스킬 획득·강화로만
18. 숙련도(영구 본체 레벨)=습득 가능 기술의 폭(tier) 해금. 스탯 안 올림
19. 판중 성장=전투 보상 화면(항상 기술 3택1: 새 스킬 or 강화/중첩). 범용 강화권=상점에서만
20. 스킬 강화=작가 설계 티어(Lv1→2→3)

**로그라이크 루프·런**
21. 기억 회랑 하이브리드: 본체 영구·안전, 출격은 사본, 판중 성장 휘발, 일부만 계승
22. 두 트랙 분리(하데스): 한 판 자기완결 + 영구 계승 별도 레이어. 계승=해금·자원 주력, 레벨 소량
23. 런: 분기 노드맵, 6노드(일반/엘리트/상점/인카운터/휴식/보스), 다층(기본 3층, parameterizable), 전멸=실패/최종보스=클리어, 웨이브=노드 내부 연속 파도

**포메이션 (차별점)**
24. 창발적 위치 효과: 열별 보너스 + 총량보존(몰빵vs분산). 일반전투=표준, 보스=기믹 변주. 적 진형보너스=보스전만
25. 동적 재배치=핵심 전술. 단 이동기 있는 유닛만 이동 가능

**엔진·인프라**
26. 아키텍처: 헤드리스 순수 코어 + 다중 뷰(텍스트/CLI=AI·모니터링 1급, 웹=사람 후순위)
27. AI는 스크린샷 아닌 구조화 관측+터미널로 플레이. 결정에 필요한 모든 정보가 observation에
28. 시드 기반 결정론 + 리플레이 + 이벤트 로그(= 애니메이션 구동원)
29. 스택=TypeScript 단일. 데이터 주도 설계 1급 원칙
