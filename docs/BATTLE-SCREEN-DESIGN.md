## B. HUD 마감

- **각진 + 대각선 컷(chamfer) 패널** — 현대 포켓몬 SV식 미래지향. 둥근 모서리 ❌, 사각 모서리를 대각선으로 깎음.
  - **기술**: `StyleBoxFlat`은 둥근 모서리만 → 안 됨. **커스텀 `ChamferPanel` 위젯**(`scenes/ui/chamfer_panel.gd`, `@tool`, `_draw`로 8각 폴리곤 + 테두리 선, exported `cut_tl/tr/br/bl`·`chamfer`·`fill/border`·`pad`). 9-slice 불요, 해상도 독립.
- **★ "Bar" 개념 폐기 — 독립 앵커 패널** (2026-06-13 사용자 결정): 하나의 컨테이너(Bar/HBox)에 종속시키면 ① 자식이 밖으로 못 나옴 ② 패널 간 겹침/크롭아웃 연출 불가 ③ 컨테이너 강제 레이아웃. → **각 HUD 패널(유닛/툴팁/스킬/턴넘김/행동서열)을 `CanvasLayer` 위 독립 앵커 Control**로. 자유 위치·겹침·z순서·크롭아웃 가능.
- **★ 에디터에서 디자인** — 모든 패널 위젯 `@tool` → 게임 실행 없이 **에디터에서 chamfer·배치가 그대로 보임.** 위치·외형(컷/색/크기)은 **에디터 인스펙터에서 디자이너가 직접**, 코드는 노드를 찾아 **내용만 채움**(populate, 런타임). 역할 분리: 구조/배선=코드, 시각/배치=에디터.
- **색** = 다크 테마(#14161c 배경 / 패널 #1d2029·#252a36) + 진영색 accent(아군 #5aa9e6 / 적 #e6685a), 현재 행동자 강조 = accent #ffd166.
- **구성**(스케치 `전투 하단 HUD.jpg` 참고, 독립 패널): 유닛 패널(좌, 오른쪽 상단 컷) · 툴팁(좌상단 컷) · 스킬 슬롯(우상단 컷) · 턴 넘김 버튼. 각자 떠 있어 에디터에서 자유 배치.

## C′. 보드 유닛 렌더 아키텍처 (3D 카드 + 2D 머리위 오버레이) — 2026-06-13 확정

원근 3D + 월드공간 빌보드는 **칸↔스프라이트·바↔카드가 카메라 각도에 따라 어긋남**(서로 다른 높이가 다른 화면 위치로 투영). → **해법 B 채택**:
- **카드(스프라이트) = 3D** — `unit_token.gd`. 발-피벗(`center_offset`)을 칸에 붙이고 카메라 쪽으로 너지 후 풀 빌보드(카메라 평행). 칸 위에 선 입간판.
- **이름·HP바·상태 = 2D 오버레이** — `overhead_label.gd`(CanvasLayer 위 Control). `battle.gd._process`가 매 프레임 `camera.unproject_position(token.head_world_pos())`로 카드 머리 위 화면좌표에 중심 배치. → 항상 선명·일정 크기·완벽 정렬·겹침 제어, 하단 HUD와 같은 2D 시각언어.
- (대안 A=전부 한 평면 빌보드/SubViewport 합성은 미채택 — 깊이에 따라 UI 가독성 저하.)

## C. 유닛 토큰 (도트 들어오기 전 "완성되어 보이게")

- **바닥 베이스 링**(진영색 발광 타원/육각) + 그 위 **세운 카드 토큰**(이니셜/이모지 → 도트 들어오면 그 자리 교체) + 그림자 + 상단 네임플레이트.
- **베이스 링 = 선택/타겟/도달 글로우 겸용** → slice G의 2.5D 가림 문제(서 있는 카드가 바닥 하이라이트 가림) 해소. 바닥 링은 카드에 안 가린다.
- HP바·상태칩 = 현행 유지(카드 위, slice E).

## D. 모션 · VFX (이벤트 로그 → 타임라인)

절제 톤 = "포켓몬 배틀 애니메이션 OFF" 수준. **화면 흔들림·히트스톱 없음.**

## I. 행동서열 스트립 (상시)

**좌측 세로 포트레잇 토큰 스트립** (현 우측 텍스트 칩 → 교체). 위치 = 화면 좌측 가장자리, 하단 HUD 바 위 공간.

- **배경 패널**: 디버그 = 투명 + 테두리만(스크롤 영역 가시화). **본편 = 테두리 없이 전투 배경 위에 토큰만**(토큰 사이 빈공간 보여도 OK).

## J. 주사위 연출 (라운드 시작 SPD 굴림) — ✅ 행동서열과 **통합**(`turn_order.gd`)

**별개 모달 폐기 → 행동서열과 한 컴포넌트**(웹 `timelinePanel` 정신: 같은 것이 모드만 전환, 별개 오버레이 없음). SPD = `speedMin~speedMax` 범위 굴림(+mod)이라 **눈금 숫자**가 핵심.

- **★ 같은 노드가 끝까지 살아남아 변신**(웹 `.trow`가 `.rolling` 클래스만 벗는 것과 동일): 굴림 행 = 라이브 토큰 = **하나의 공유 행 위젯**(`_make_row` = PanelContainer>VBox[line1 HBox(mark·이름·주사위·±보정·SPD), line2]). 노드 교체·크로스페이드 없음.
- **시퀀스**(4단계): ① 굴림→차례 확정(숫자 릴, BACK pop) → ② **재배치 애니**(각 행 y를 순위 위치로 슬라이드) → ③ **형태 전환 애니**(독립 단계, 제자리: 주사위/보정 페이드아웃 + 박스 테두리·SPD·현재 두 줄 페이드인 + 폭/높이 보간) → ④ **도킹**(토큰이 된 행이 측정된 레일 위치로 스태거 슬라이드, 그대로 정착). 도킹 직후 `update`는 `_just_docked`로 1회 재구성 생략(같은 노드 유지).
- **live 형태(§I)**: 현재=두 줄(이름 16 + "SPD·현재 턴" accent)·넓은 토큰(176)·accent 테두리 / 일반=단일행(150) / ⚡끼어들기 민트 / ✓완료·†사망 흐림. 현재 판정=cursorIndex(obs).
- **눈금**: 숫자 릴(`_process` 0.06s 순환, roll 확정). SPD>6이라 핍 주사위 대신 **숫자**. 총합 speed 표기 없음(최종 SPD=토큰).
- **페이싱**: **매 라운드 자동**(battle.gd가 이벤트 델타의 roundStart 감지 → 라운드당 1회) + **클릭 스킵**(남은 지연 생략). dim 오버레이가 굴림 중 HUD 입력 차단.
- **남은 폴리시**: 토큰 행 chamfer 컷, 현재 행동자 초상화.

## K. 화면 적응 (해상도/화면비)

화면비는 16:9 보장 없음 → **두 층으로 적응** (project.godot, 적용 완료):
- **스케일링** = `window/stretch/mode=canvas_items` + `aspect=expand` + 기준 1280×720. 기준 해상도로 렌더 후 비율 스케일(UI·폰트 같이), `expand`로 레터박스 없이 남는 공간을 실 영역으로.
- **리플로우** = 각 패널 **앵커**(고정 픽셀 ❌). 유닛=좌하단·턴넘김=우하단·스킬=하단 중앙 확장·행동서열=좌측 가장자리. 넓어지면 가운데 보드/스킬이 늘고 가장자리 HUD는 제자리. → **독립 앵커 패널(§B)이 곧 반응형 구조.**
- 보드(3D)=`Camera3D.keep_aspect`(높이 고정) — 넓은 화면일수록 좌우로 더 보임.
- **검증**: 720p·울트라와이드(2560×1080) 헤드리스 캡처로 리플로우 확인(`642d32f`).
- **정책(PC 우선)**: 흔한 PC 해상도(720p~1440p·16:9/16:10·약한 울트라와이드)는 위로 커버. 극단 세로/모바일 = 레이아웃 브레이크포인트 필요 → 향후 별도 작업(범위 밖). 디자인 시안은 **"고정 픽셀"이 아니라 "앵커된 구역"(가장자리 고정/중앙 확장)**으로 사고.
