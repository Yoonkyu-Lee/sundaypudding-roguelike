# Slice Wrap (종료 게이트)

슬라이스를 끝냈다고 판단하면 이 순서를 따른다. (CLAUDE.md 체크리스트의 실행판)

## 1. 자동 게이트

```bash
npm run check
```

줄 수 캡 · 코어 순수성 · 배럴 규율 · tsc · test · 데모 해시 회귀를 한 번에 본다. **FAIL이면 멈추고 고친다.** WARN(줄 수 근접 등)은 지금 분리할지 판단. 의도한 동작 변경이라 데모 해시가 바뀐 거면 `npm run check -- --update`로 골든 갱신.

## 2. 문서 갱신 (필요한 것만)

- **`docs/CODE-MAP.md`**: 새 파일/함수/기능 위치를 모듈 트리·색인에 반영. (거의 항상 갱신)
- **`docs/GAME-DESIGN.md`**: 8.7 구현 상태 갱신. 새로 확정된 규칙 반영. 프리미티브를 추가했으면 **8.8 카탈로그에 추가**.
- **`CLAUDE.md`**: 새 불변 규칙/습관이 생겼을 때만. (비대해지지 않게)
- **`README.md`**: 실행법이 바뀌었을 때만.

## 3. 문서 길이 (#6)

`npm run check`의 문서 길이 WARN을 확인. 비대하면 분리/축약을 제안한다 (스펙은 길어도 되지만 CLAUDE.md는 짧게 유지).

## 4. 분류 태그

이번 변경이 **`[데이터-온리]`**인지 **`[엔진 프리미티브 추가]`**인지 확정. 프리미티브 갭이었다면 `/slice-plan`에서 사전 승인받았는지 확인.

## 5. 커밋

한 줄 메시지 + 분류 태그. 예: `feat: 상점 노드 본구현 [데이터-온리]`. 실험성이면 브랜치 → `main` merge. **푸시는 사용자가 명시할 때만.**
