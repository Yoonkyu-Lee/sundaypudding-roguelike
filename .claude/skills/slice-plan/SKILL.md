# Slice Plan (진입 게이트)

새 기능/리팩토링을 시작하기 **전에** 이 템플릿을 채워 사용자에게 보여준다. 채우다 막히면 그게 신호다 — 설계가 덜 됐거나 프리미티브 갭이다. 코드는 이 다음에.

## 채울 것 (5줄, 짧게)

1. **무엇**: 이번 슬라이스 한 줄 정의.
2. **데이터 vs 엔진** (CLAUDE.md "데이터 vs 엔진 경계", GAME-DESIGN 8.8):
   - 기존 프리미티브 조합으로 **원자적으로 표현 가능?** → 가능하면 **`[데이터-온리]`**: 어느 `src/data/*` 파일 + 어느 `types/content.ts` 스키마 조합인지 적는다.
   - 불가능하면 **`[엔진 프리미티브 추가]`** = 프리미티브 갭. **STOP.** 아래 문구 그대로 출력하고 사용자 승인을 기다린다:
     > "이 기능은 새 엔진 프리미티브가 필요합니다 — **[무엇]**. 기존 [관련 프리미티브]로는 원자적으로 불가(이유). 추가 위치: `types/content.ts` + `core/<module>`. 데이터-온리가 아닙니다."
3. **들어갈 모듈**: `src/core/<combat|run|ai>/...` 또는 `src/data/...` 중 어디. 소비는 **배럴/파사드 경유**. (트리: `docs/CODE-MAP.md`)
4. **웹 범위** (CLAUDE.md 평행 개발): 플레이어 표면이 있나? 코어 generic 뷰(상태칩/HP바 등)로 커버되나, 아니면 `src/web` 갱신 필요? 새 시각 어포던스가 필요한 경우만 프론트 작업.
5. **크기**: 대상 파일 현재 줄 수. ~300 근접/초과면 **먼저 분리하고**(배럴 유지) 추가한다. (`npm run check`가 줄 수도 본다)

## 끝나면

- `[데이터-온리]`면 바로 구현. `[엔진 프리미티브 추가]`면 승인 후 구현.
- 구현이 끝나면 **`/slice-wrap`**로 닫는다(게이트 + 문서 갱신 + 커밋).
